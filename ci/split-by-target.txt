# Crates whose long/full CI run is split into ONE JOB PER TEST TARGET
# (GitHub #1337). Read by scripts/ci-crate-matrix.sh; this is the only place
# the split is chosen.
#
# Every other workspace member runs as ONE job:
#     cargo test -p <crate> --lib --tests --release --no-fail-fast
# A crate listed here instead gets one job for `--lib` plus one per other
# target that `--tests` would run (each `--test`, and each `--bin`/`--example`/
# `--bench` with `test = true`), GENERATED from `cargo metadata`, never
# hand-listed, so a new test file gets its own job the moment it exists. The
# union of the shards is exactly the target set of `--lib --tests`.
#
# WHY SPLIT AT ALL. A GitHub-hosted job is killed at 6 hours. A crate goes on
# this list only with evidence that it alone is too close to that. Splitting
# costs a compile of the crate's dependency closure per shard, so it is not
# free: do not list a crate "to be safe" without a number.
#
# WHAT SPLITTING CANNOT DO. It splits by test BINARY. A crate whose slow tests
# all live in `--lib` (tuas_boussinesq_solver: only a lib and one bin) gets
# nothing from it, so it is not listed; see the note at the bottom.
#
# One package name per line; `#` starts a comment. The script fails if a name
# here is not a workspace member, so the list cannot rot silently.
