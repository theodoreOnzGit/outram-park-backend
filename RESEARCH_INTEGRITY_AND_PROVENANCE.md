# Research Integrity and Provenance

## Purpose

This document records the provenance, traceability, and integrity principles used throughout this project.

The objective is to ensure scientific reproducibility, transparency, and accountability.

---

# Scientific Provenance

Major implementations should be traceable to one or more of:

- peer-reviewed literature
- technical reports
- benchmark specifications
- standards documents
- open-source reference implementations

Where practical:

- source references should be documented
- assumptions should be documented
- limitations should be documented

---

# Software Provenance

Contributors should maintain records of:

- original sources
- upstream projects
- licenses
- modifications
- validation efforts

Examples:

- OpenFOAM-derived concepts
- OpenMC-derived concepts
- NJOY-derived concepts
- CoolProp-derived concepts

---

# Open Source Compliance

Contributors should:

- preserve license obligations
- preserve attribution requirements
- document provenance chains
- respect trademark restrictions
- respect copyright restrictions

---

# AI-Assisted Development

AI systems may assist development.

Examples include:

- planning
- code generation
- documentation generation
- architecture discussions
- review assistance

AI-generated outputs are subject to:

- human review
- validation
- verification
- scientific scrutiny

AI output is not treated as authoritative.

---

# Human Responsibility

Human contributors retain responsibility for:

- scientific accuracy
- engineering judgment
- publication decisions
- code acceptance
- validation activities

---

# Reproducibility

Projects should strive for:

- version control
- documented dependencies
- benchmark coverage
- repeatable workflows
- archival of important outputs

Where possible:

- validation data should be preserved
- benchmark inputs should be preserved
- benchmark outputs should be preserved

---

# Publication Ethics

Publications should:

- acknowledge substantial AI assistance where appropriate
- accurately report methods
- accurately report limitations
- distinguish verified results from future work

Scientific conclusions shall not be delegated to AI systems.

---

# Educational Purpose

Educational simulators developed within this ecosystem are intended to:

- support learning
- demonstrate scientific principles
- aid outreach activities
- encourage scientific exploration

They are not intended to replace professional engineering judgment.

---

# Long-Term Goal

The long-term objective is a transparent and reproducible scientific software ecosystem in which:

```text
Theory
    ↓
Knowledge
    ↓
Implementation
    ↓
Verification
    ↓
Validation
    ↓
Publication
```

remains fully traceable.
