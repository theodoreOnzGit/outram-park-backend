# Validation and Verification Philosophy

## Purpose

This project develops scientific computing software.

No scientific model shall be considered validated solely because it:

- compiles successfully
- passes unit tests
- is generated by AI
- produces plausible output

Verification and Validation (V&V) are required.

---

# Verification

Verification addresses:

> "Was the model implemented correctly?"

Examples:

- unit tests
- regression tests
- conservation checks
- analytical solutions
- method-of-manufactured-solutions where applicable

Verification evaluates correctness of implementation.

---

# Validation

Validation addresses:

> "Does the model represent physical reality sufficiently well for its intended purpose?"

Validation is performed against:

- literature benchmarks
- experimental data
- reference software
- canonical test cases

Validation evaluates physical credibility.

---

# General Principles

All major models should have:

- verification strategy
- validation strategy
- traceable references
- documented assumptions
- documented limitations

---

# AI Generated Code

AI-generated code shall not bypass validation.

AI-assisted implementations shall be treated identically to manually written implementations.

Required process:

```text
AI Generation
        ↓
Human Review
        ↓
Verification
        ↓
Validation
        ↓
Acceptance
```

---

# Traceability

Every major numerical implementation should reference:

- source literature
- benchmark source
- validation cases
- implementation notes

Documentation should allow future contributors to trace:

```text
Theory
      ↓
Implementation
      ↓
Verification
      ↓
Validation
```

---

# Future Contributors

Contributors should prioritize:

- correctness
- traceability
- reproducibility
- defendable scientific results

over development speed.
