# EGSnrc `egs_interpolator`: differential test of `petir::interp_egs`

Code-to-code verification of PETIR's port of EGSnrc's `EGS_Interpolator`
(gh:#1289) against upstream compiled and run, plus its accuracy against the
exact functions. Verification only: nothing here is validation against
experiment.

| | |
|---|---|
| Port | `crates/petir/src/interp_egs.rs` |
| Upstream | EGSnrc `HEN_HOUSE/egs++/egs_interpolator.{h,cpp}`, commit `bd49a47aae3938f49f4100b8e018091861408b19` (2026-09-28), AGPL-3.0-or-later, (C) 2015 National Research Council Canada |
| Harness | `egs_interp_harness.cpp` + `stub/egs_config1.h`, built by `build_and_run.sh` |
| Pinned by | `crates/petir/tests/egs_interpolator_vs_egsnrc.rs` against `reference.txt` |
| Run | 2026-11-05, x86_64 Linux, g++ 16.2.1, glibc 2.44, Rust 1.99.1 `--release` |

## Methodology

**Upstream side.** `build_and_run.sh` compiles EGSnrc's *unmodified*
`egs_interpolator.cpp` from the gitignored clone (`vendor/egsnrc`, or
`EGSNRC_DIR`) together with the harness. EGSnrc's `egs_config1.h` is a
configure-time template and cannot compile as it stands, so `stub/` supplies
the four typedefs it would produce for a default build (`EGS_Float = double`).
`egsFatal` is defined by the harness to throw, so the guards can be observed.
The reference build uses `-O3` (EGSnrc's `egspp_gcc64_example.conf`) on
baseline x86-64, which has no FMA instruction, so no contraction can occur.

**Cases** (13), identical on both sides:

| case | construction | interval | input |
|---|---|---|---|
| `values_random` | table (`initialize(nbin, Xmin, Xmax, values)`) | `[0.25, 7]`, 33 values | splitmix64 seed 1, in `[-5, 5)` |
| `values_steps` | table | `[-1, 1]`, 9 values | `0 0 1 1 1 -2 -2 5 5` (jumps, sign changes) |
| `coefficients` | existing `a`, `b` (`initialize(nbin, Xmin, Xmax, A, B)`) | `[1, 4]`, 21 | splitmix64 seeds 2, 3 |
| `func_exp` | function, fixed bins | `[0, 5]`, 65 points | `exp(x)` |
| `func_powlaw` | function, fixed bins | `[0.1, 10]`, 200 | `x^-1.5` (`pow`) |
| `func_rational` | function, fixed bins | `[-3, 3]`, 101 | `1/(1+x^2)` (no libm) |
| `func_logvar` | function, fixed bins, log variable | `u = ln E`, `E` in `[1e-3, 20]`, 128 | `exp(-0.8u) + 2` |
| `adaptive_exp` | adaptive, `nmax 1024`, `accu 1e-4` | `[0, 5]` | `exp` |
| `adaptive_powlaw` | adaptive, `4096`, `1e-6` | `[0.1, 10]` | `x^-1.5` (falls back to `nmax`) |
| `adaptive_rational_small` | adaptive, `nmax = 8` (the `nmax <= 9` branch) | `[-3, 3]` | rational |
| `adaptive_cap` | adaptive, `100`, `1e-8` | `[0, 30]` | `exp` (falls back to `nmax`) |
| `adaptive_rational` | adaptive, `1024`, `1e-5` | `[-3, 3]` | rational (falls back to `nmax`) |
| `adaptive_logvar` | adaptive, `1024`, `1e-4` | log variable as above | `exp(-0.8u) + 2` |

On the Rust side the functions use `petir::real::exp` and `real::powf`;
upstream uses glibc's `exp` and `pow`.

**What is recorded**, as exact IEEE-754 bits: every `a[i]` and `b[i]` for
`i = 0..=n`; every `x` at which the function was called, in call order; and,
for each query, `interpolate(x)` and `getIndex(x)`, plus, for `x` in
`[xmin, xmax]`, `interpolateFast(x)`, `getIndexFast(x)` and
`interpolateFast(getIndex(x), x)`. Queries: every node and every bin
midpoint; 15 special points (`xmin`, `xmax`, the adjacent doubles on both
sides of each, `xmin-1`, `xmax+1`, `xmin-L`, `xmax+L`, `-inf`, `+inf`, NaN,
`+0`, `-0`); and 100 000 splitmix64 points on `[xmin - 0.1L, xmax + 0.1L]`.

**Comparison.** The committed `reference.txt` (569 lines) holds per-case
FNV-1a digests and counts of the three streams, the bin count, 31 explicit
query vectors and up to 8 coefficient pairs per case, and the guard results.
The test replays every case through PETIR and requires all of it to match.
The ignored test `full_dump_comparison_table` compares value by value against
the harness's full dump (366 MB, not committed) and prints the table below.

**Pass criterion:** bit-identical, every recorded value.

## Prediction (written 2026-11-05, before the first run)

- **Tabulated cases** (`values_random`, `values_steps`, `coefficients`): the
  inputs are bit-identical on both sides (generated by integer splitmix64),
  and construction and evaluation are `+ - * /` in the same order, compiled
  with no FMA contraction. **Predicted: every coefficient, value and index
  bit-identical.**
- **Rational function cases** (`func_rational`, `adaptive_rational*`): no libm
  call. **Predicted: bit-identical, including the sequence of points at which
  the function is called.**
- **exp / pow cases** (`func_exp`, `func_powlaw`, `func_logvar`,
  `adaptive_exp`, `adaptive_powlaw`, `adaptive_cap`, `adaptive_logvar`): the
  Rust side uses PETIR's `real::exp` / `real::powf` (ARM optimized-routines
  ports); glibc 2.44's `exp` and `pow` are the same ARM algorithms, but glibc
  selects an FMA variant at run time on an FMA-capable CPU, which can round
  differently in rare cases. **Predicted: bit-identical on nearly all nodes;
  any difference is 1 ulp in a node value, propagating to that node's two
  bins, and possibly changing an adaptive bin count only if it sits on the
  `accu` boundary (not expected).** Call sequences predicted identical
  whenever the bin counts agree.
- **Sensitivity builds** (not the reference): `-march=native` lets GCC
  contract `a[i] + b[i]*x` and `ax + bx*x` into FMAs, predicted to differ in
  the last bits of many values; `-ffast-math` predicted to differ as well.

## Results (2026-11-05)

**Bit-identical on every value of every case**, including the `exp`/`pow`
cases. The prediction's possible 1-ulp node differences did not occur:
PETIR's `exp`/`pow` and glibc 2.44's agreed on all 12 511 function
evaluations, so the function-built cases are bit-identical through
construction too. No residual needs the `1e-8` allowance.

| case | bins | function calls | values compared | bit-identical | worst difference |
|---|---|---|---|---|---|
| `values_random` | 32 | 0 | 450 477 | 450 477 | 0 |
| `values_steps` | 8 | 0 | 450 144 | 450 144 | 0 |
| `func_exp` | 64 | 65 | 451 137 | 451 137 | 0 |
| `func_powlaw` | 199 | 200 | 452 175 | 452 175 | 0 |
| `func_rational` | 100 | 101 | 451 494 | 451 494 | 0 |
| `func_logvar` | 127 | 128 | 452 019 | 452 019 | 0 |
| `adaptive_exp` | 256 | 513 | 453 228 | 453 228 | 0 |
| `adaptive_powlaw` | 4095 | 8 193 | 499 092 | 499 092 | 0 |
| `adaptive_rational_small` | 7 | 8 | 449 811 | 449 811 | 0 |
| `adaptive_cap` | 99 | 229 | 451 368 | 451 368 | 0 |
| `adaptive_rational` | 1023 | 2 049 | 462 279 | 462 279 | 0 |
| `adaptive_logvar` | 512 | 1 025 | 455 706 | 455 706 | 0 |
| `coefficients` | 20 | 0 | 449 886 | 449 886 | 0 |

"Values compared" counts coefficients plus evaluation outputs (values and
indices); the function-call sequences (digest `calls`) and bin counts are
also identical for every case.

**Guards.** Upstream raises `egsFatal` for `nbin = 1`, `Xmin = Xmax`,
`Xmin > Xmax` and adaptive `nmax = 1`; PETIR returns `Invalid`, `Domain`,
`Domain`, `Invalid`. A NaN `Xmin` passes upstream's check and PETIR's.

**Upstream defect found.** EGSnrc's function constructor and `a`/`b`
constructor call `initialize(nbin, Xmax, Xmax, ...)`, passing `Xmax` for
`Xmin`. Run: both raise `egsFatal` ("Xmin must be > Xmax, I got Xmin=1
Xmax=1") on valid input (`[0, 1]`), while `initialize` with the same
arguments succeeds. The port follows `initialize`. (The message itself also
inverts the condition: it means `Xmax > Xmin`.)

### Sensitivity: upstream built differently (not references)

Upstream against itself, matched on `(kind, x)` (the query generator is
contracted too under `-march=native`, so some queries differ and only common
ones are compared):

- **`-O3 -march=native`** (FMA available, GCC contracts by default): 19 to
  54 % of the compared values per case differ, the worst per case between
  4.4e-16 and 1.2e-10 relative, the larger ones where a value crosses zero;
  0 to 1 498 `getIndex` values per case move to the neighbouring bin at bin
  edges (`ax + bx*x` fused), which on the discontinuous `coefficients` table
  changes values by O(1) (worst 4.0 relative). PETIR
  matches the non-contracted build by design (no FMA in the port).
- **`-O3 -ffast-math`** (used by some EGSnrc example configs): a NaN query
  returns `fmin` and index 0 instead of `fmax` and `n-1` (fast-math assumes
  no NaN), and `pow(x, -1.5)` is rewritten, moving power-law nodes by a few
  ulps (83 422 of 452 173 `func_powlaw` and 96 488 of 499 090
  `adaptive_powlaw` values differ). Every other value is identical.

## Accuracy against the exact functions (2026-11-05)

Measured by the tests in `egs_interpolator_vs_egsnrc.rs`, 199 999 interior
points per case:

| case | bins | max relative error | bound or claim |
|---|---|---|---|
| `exp`, fixed, `[0,5]` | 64 | 7.632e-4 | `h^2/8 e^h` = 8.249e-4 (piecewise-linear bound) |
| `x^-1.5`, fixed, `[0.1,10]` | 199 | 7.855e-2 | 2.126e-1 (first bin's bound) |
| `exp`, adaptive, `accu 1e-4` | 256 (converged) | 4.768e-5 | `accu` = 1e-4 |
| `exp(-0.8u)+2`, adaptive, `accu 1e-4` | 512 (converged) | 2.969e-5 | 1e-4 |
| `1/(1+x^2)`, adaptive, `accu 1e-5` | 1023 (`nmax` fallback) | 8.600e-6 | 1e-5 (not guaranteed on fallback) |
| `exp` on `[0,30]`, adaptive, `accu 1e-8` | 99 (`nmax` fallback) | 1.153e-2 | not met; under `h^2/8 e^h` = 1.554e-2 |

Upstream claims (header) that the adaptive interpolator's relative error does
not exceed `accu`; its code checks the relative error at the bin midpoints.
Measured, the claim holds everywhere sampled when the loop converges, and is
not guaranteed when it falls back to `nmax` bins, as upstream documents.

## Reproduce

```bash
EGSNRC_DIR=<path to EGSnrc clone> crates/petir/verification_and_validation/egsnrc_interpolator/build_and_run.sh /tmp/egs_interp
EGS_INTERP_FULL_DUMP=/tmp/egs_interp/full_dump.txt cargo test --release -p petir \
  --test egs_interpolator_vs_egsnrc -- --ignored --nocapture
cargo test --release -p petir --test egs_interpolator_vs_egsnrc
```
