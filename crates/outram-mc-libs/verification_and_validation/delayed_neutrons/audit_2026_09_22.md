# Audit: what delayed-neutron physics is actually present

GitHub **#262, scope item 1** — *"Audit and document what delayed-neutron
physics is actually present today."* Performed 2026-09-22.

The issue flags this as unverified: *"`delayed` appears in
`src/physics/fission.rs` and `src/material/nuclide.rs`, so some delayed-neutron
handling exists, but whether the delayed-group data and precursor decay
constants are actually sampled has not been verified in this audit."*

It is now verified. The answer is worse than "partial".

## Finding 1 — the data exists, in full, and is unused

`njoy-outram-park-fork` parses the delayed-neutron data completely:

| what | where |
|---|---|
| MF=1/MT=455: `NNF` precursor groups, decay constants λ_k, ν̄_d(E) | `src/nuclear_data/delayed.rs` (`DelayedNuBar`) |
| MF=5/MT=455: per-group abundances p_k(E) and delayed spectra χ_k(E') | `src/nuclear_data/delayed.rs` |
| multigroup collapse of the above | `src/nuclear_data/delayed_mgxs.rs` |

`outram-mc-libs` references **none of it**:

```bash
grep -rn "nuclear_data::delayed\|DelayedNuBar\|delayed_mgxs" --include=*.rs \
     crates/outram-mc-libs/src/
# (no output)
```

## Finding 2 — the transport folds delayed into prompt, and says so

`src/physics/fission.rs:12`:

> **Delayed neutrons** are folded into the total ν̄ and treated as prompt — the
> standard eigenvalue approximation (prompt + delayed born at the same instant).

That is a legitimate and clearly-labelled approximation for a `k`-eigenvalue
calculation, and it is **not** the defect. It is the reason there is no λ_k, no
precursor, and no emission time anywhere in the transport loop.

Its consequence is the one that matters for #262: **every kinetics quantity the
issue asks for is unavailable by construction**, not merely unimplemented.
`beta_eff` needs delayed and prompt ν̄ separately; `Lambda` needs a
1/v-weighted flux; both need the split this approximation removes.

## Finding 3 — `DelayedGroupFilter` can only ever tally ZERO

This is the defect.

`src/tally/filter.rs` has a `DelayedGroupFilter` with one bin per precursor
group, and `FilterEvent` carries `delayed_group: Option<usize>`. The filter is
registered in `FilterKind` and dispatches correctly.

But **nothing in production ever sets that field**. Every site that assigns
`Some(..)` is a test:

```
tests/tally_filters_vs_definitions.rs:391:  delayed_group: Some(3),
tests/tally_filters_vs_definitions.rs:404:  delayed_group: Some(4),
tests/tally_filters_vs_definitions.rs:435:  delayed_group: Some(1),
```

So in any real run the filter sees `None` at every event and bins nothing. A
tally carrying it returns **exactly zero**, with no error, no warning and no
empty-result diagnostic.

That is the same failure shape as #259's aliased boundary condition and as the
`mt_matches` trap recorded in #261: the code runs, the output is
well-formed, and it answers a different question — here, the question "what is
the delayed-neutron fission rate in group k?" is answered "zero" for every k.

**It is arguably worse than those two**, because zero is a value a physicist
might accept. A delayed-group tally on a non-fissile region *should* be zero,
so the wrong answer is indistinguishable from a right one without knowing the
geometry.

## What this means for the rest of #262

Scope items 2 and 3 (`delayed-nu-fission`, `prompt-nu-fission`,
`inverse-velocity`, `decay-rate`, then `beta_eff` and `Lambda` by the k-ratio
route) are **not** additions on top of working delayed-neutron physics. They
require first splitting ν̄ into prompt and delayed in the transport loop and
carrying the sampled precursor group on the event — which is the very thing
`fission.rs` deliberately does not do.

The honest ordering is therefore:

1. Make `DelayedGroupFilter` either work or refuse. A filter that silently
   tallies zero should not remain reachable. **Refusing is cheap and is the
   safe interim**; making it work is item 2 below.
2. Split ν̄: consume `njoy-outram-park-fork`'s `DelayedNuBar` (it is already
   there), sample prompt-vs-delayed at fission, and record the precursor group
   on the event.
3. Only then the four scores, then the k-ratio `beta_eff`/`Lambda`.
4. IFP (`src/ifp.cpp`) last, as the issue already orders it.

## What was NOT checked

- Whether `njoy-outram-park-fork`'s MF=1/455 and MF=5/455 parsers are correct.
  They have their own tests; this audit only established that they exist and
  that `outram-mc-libs` does not call them.
- Whether the folded total ν̄ is itself right. It is MF=1/MT=452 (prompt +
  delayed), which is the correct quantity for the approximation being made.
