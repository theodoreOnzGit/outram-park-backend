## Crossing a surface inside a translated lattice element

`cross_surface_in_frame` is a method of the extension trait `GeometryExt`
(`crates/outram-mc-libs/src/geometry/crossing/mod.rs`, implemented for
`outram_blender::csg::geometry::Geometry`), so the call from the history is a
trait call; rust-analyzer resolves it to the impl (a hand-filled hop written
for it was reported by the tool as resolved and removed). What it does, read
from the source: `transport_history_vr` calls
`geom.cross_surface_in_frame(i_surf, &path, d_bound.coord_level, r, u, seed)`
when the boundary is nearer than the collision; the implementation converts
`r` into the frame of the level that owns the surface (`coord_level`) before
computing the normal, then applies the boundary condition (vacuum leak,
reflection, white, or transmission with a nudge along the normal) and returns
which side it landed on. Handing it the **global** position instead was the
2026-09-14 defect that put LCT-008 2300 pcm high (case study in the lesson;
`9387f6b0de`).
