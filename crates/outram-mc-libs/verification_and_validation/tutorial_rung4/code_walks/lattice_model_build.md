## Where there is no function: the lattice and universe types are data

The lattice, universe and cell are **plain data**, built by struct literals in
`build_geometry`, so no call chain reaches them (filled by hand, from reading
`common/lct008_model.rs` and `crates/outram-blender/src/csg/`):

- `RectLattice { id, n: [nx, ny, 1], lower_left, pitch, universes, outer }`
  (`crates/outram-blender/src/csg/lattice/rect.rs`) holds the grid. `universes`
  is a flat vector indexed `nx * iy + ix` with `iy` increasing along +y, so
  `build_geometry` reverses OpenMC's top-down rows when it fills it.
- `Lattice::Rect(..)` (`lattice/mod.rs`) is the enum the geometry stores, so a
  hexagonal lattice dispatches the same way (enum, not trait object, per the
  workspace Rust rules).
- `Universe { id, cell_indices }` (`csg/universe.rs`) is a list of cells.
- `Cell::material(..)` / `Cell::fill(.., CellFill::Lattice(l) | CellFill::Universe(u), ..)`
  (`csg/cell.rs`) is where the nesting happens: a cell whose fill is a lattice
  or another universe.
- `Geometry { surfaces, cells, universes, lattices, root_universe }`
  (`csg/geometry.rs`) is the whole model; in LCT-008 the root is universe 0
  (the core cylinder), which is filled by the 7 × 7 core lattice (id 99),
  whose tiles are assembly wrapper universes filled by 15 × 15 pin lattices,
  whose elements are pin universes 1 (all water), 2 (fuel rod) and 3 (pyrex).

These types moved from outram-mc-libs to outram-blender on 2026-10-02 (#486);
`outram_mc_libs::geometry::{lattice, universe, cell, geometry}` re-export them.
