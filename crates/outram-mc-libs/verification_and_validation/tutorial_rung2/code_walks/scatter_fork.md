# Code walk: lethargy and the bottom of the slope — the three-way scatter fork

Tutorial rung 2 (GitHub #524), steps 3 and 4. Generated by `kovan-cli
code-walk` (#523); see `one_collision_with_carbon.md` for how the blocks are
regenerated and what "filled by hand" means.

**There is no function that computes lethargy, ξ or "114 collisions to
thermal".** They emerge from the transport loop repeating one collision. What
the code has is a fork, taken afresh at every scatter (filled by hand from the
`else` scatter branch of `transport_history_vr`,
`crates/outram-mc-libs/src/physics/transport_csg.rs`):

1. **Bound atom, S(α,β):** `nuc.sample_thermal(e, seed)` returns
   `Some((e_out, mu_lab))` when the nuclide carries a thermal table and `e` is
   below its cutoff (a few eV for graphite: the tape's `E_max`, since #459). Carbon
   in graphite takes this branch at the bottom of the slope; the law comes
   from the workspace's THERMR port (`ThermalScattering`, built from
   `tsl-crystalline-graphite.endf`). The outgoing direction is
   `rotate_direction(u, mu_lab, seed)`, lab frame, no CM transform.
2. **Free gas:** otherwise `free_gas_elastic_scatter_dbrc` samples the target
   nucleus's thermal motion below 400 kT (and, for a resonant nuclide with a
   DBRC table, inside its window up to 1 keV, with DBRC's rejection), so the
   neutron can gain energy.
3. **Target at rest:** above that, the same function holds the nucleus still
   and calls `two_body_scatter_with_mu` — step 2's kinematics, and where α and
   ξ live.

Step 4a's bug (before bead `op-50vu`, 2026-09-11) was branch 3 being used all
the way down: a neutron that can only lose energy cools without bound
(`free_gas_elastic_scatter`'s doc comment records `⟨E⟩ → 1e-27 eV` after 400
collisions at 600 K). Branch 2 is the fix.
