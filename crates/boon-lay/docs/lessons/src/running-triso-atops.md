## The nuclide model: 84 nuclides, five transport groups

TRISO-ATOPS supports a fixed table of **84 nuclides**, with half-lives from the
IAEA Live Chart, not ENDF
([`nuclide_database.rs`](https://github.com/theodoreOnzGit/outram-park-backend/blob/@@COMMIT@@/crates/boon-lay/src/triso_atops_fork/nuclide_model/nuclide_database.rs)).
Each is a
[`TrisoAtopsNuclide`](../../api/boon_lay/triso_atops_fork/nuclide_model/struct.TrisoAtopsNuclide.html)
(name, $Z$, $A$, half-life, parents) whose
[`ElementGroup`](../../api/boon_lay/triso_atops_fork/nuclide_model/enum.ElementGroup.html)
follows from $Z$:

| Group | Elements | Release model (rung 4) |
|---|---|---|
| noble gas | He, Ne, Ar, Kr, Xe, Rn | empirical $\langle R/B\rangle$ |
| halogen (TRISO-ATOPS's grouping) | F, Cl, Br, I, At, **plus Se and Te** | same correlation |
| special metal | Rb, Sr, Cs, Ba, Eu | Booth sphere |
| silver | Ag, Pd | breakthrough through SiC |
| other | everything else | fixed $\langle R/B\rangle = 10^{-5}$ |

Se and Te in the halogen group is upstream's choice, kept.

## Run files: two formats

Upstream passes a bare array of fifteen constants between every layer,
indexed by position (`constants[6]` is the plate-out rate). The port parses a
run once into a named, `uom`-typed
[`RunConfig`](../../api/boon_lay/triso_atops_fork/run_file/struct.RunConfig.html),
so an index slip cannot happen silently.

- **The port's own [`RunFile`](../../api/boon_lay/triso_atops_fork/run_file/struct.RunFile.html):**
  bare numbers with fixed units (metres, s⁻¹, run and irradiation time in
  years).
- **Upstream's GUI-written file,
  [`read_upstream_run_file`](../../api/boon_lay/triso_atops_fork/run_file/upstream/fn.read_upstream_run_file.html):**
  `[value, unit]` pairs with each unit checked, inline arrays or CSV paths for
  nuclides, inventories and temperature profiles, and upstream's
  `check_run_file` rules (including that the failure fractions do not sum
  above 1). It needs `serde_json`, which is why that is a library dependency.

**Not ported, deliberately:** the Tkinter GUI, the logging set-up, the error
counter (a `Result` does its job) and the `argparse` entry point. A headless
library that must build for Android has no use for them.

## The check

`run_file::upstream` is verified code to code against upstream's
`process_run_file` on GUI-written files (gh:#449), with reference values from
running upstream (`dev/gen_upstream_run_file_reference.py`,
`tests/triso_atops_upstream_run_file.rs`). The name normalisation is part of
the third code-to-code pass (31 cases). See
[rung 7](../../tutorials/triso-atops/coolant.html#step-2-through-the-graphite-and-into-the-helium) for the
whole suite's numbers.

**Re-run 2026-10-04** (`develop` atop `5e802df3a4`, `--release`): pass. Two
GUI-style files are read identically to upstream, and four malformed ones (a
wrong unit, an unknown time unit, failure fractions summing to 1.10026 and
to exactly 1.0) are rejected by both codes with the same error.
