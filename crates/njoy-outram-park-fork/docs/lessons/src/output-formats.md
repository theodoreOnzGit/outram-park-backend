# Extended: other codes' formats

> **Research, education and V&V only.** Not for reactor operation, licensing,
> safety decisions or emergency response.

> **Review status: first draft, 2026-10-04, AI-assisted, not yet reviewed by a
> human.**

*Part II, extended deep dive. These modules take GROUPR's multigroup output
(rung 7) or a PENDF and write it in the format another family of codes reads.
OUTRAM PARK's own transport codes need none of them, which is why several are
not ported. Each module is a visible row here and in the
[coverage table](./coverage.md), ported or not.*

## The question

GROUPR's output (a GENDF tape) is NJOY's own format. **What do lattice codes,
discrete-ordinates codes and resonance calculators expect instead, and how
much of NJOY's formatter family does this crate carry?**

## The modules, one by one

| module | writes | for | status here | check |
|---|---|---|---|---|
| **WIMSR** | WIMS-D / WIMS-E library: cross sections, P0/P1 matrices, resonance integrals vs T and σ₀ | WIMS lattice codes | **ported**, `wimsr::run_gendf` | WIMS-D library **byte-identical** to NJOY2016's on U-238 (29 groups, 6 σ₀) |
| **DTFR** | DTF-IV card-image tables, CLAW format | discrete-ordinates (Sₙ) and diffusion codes | **ported**, `dtfr::run_with_input` | U-238 CLAW tables vs NJOY2016: worst 4.9e-6 against a 2e-5 gate (first recorded [2026-10-04](./remeasured.md)) |
| **RESXSR** | pointwise resonance cross sections (RESXS) for 4–200 eV | intermediate-resonance self-shielding calculators | **ported**, `resxsr::run_resxs` | H-2 RESXS stream **byte-identical** to NJOY2016's (2 124 bytes) |
| **MIXR** | a new PENDF of weighted sums (elements from isotopes, mixtures) | plotting, elemental data | **ported**, `mixr::run_mix` | H-2/Be-9 0.5/0.5 mix vs NJOY2016: 787 points per MT, **identical** (first recorded [2026-10-04](./remeasured.md)) |
| **MATXSR** | MATXS generalised material cross-section files | TRANSX → many transport codes | **`NotPorted`** stub | none |
| **CCCCR** | CCCC files ISOTXS, BRKOXS, DLAYXS | fast-reactor codes (US FBR programme) | **`NotPorted`** stub | none |
| **POWR** | EPRI-CELL / EPRI-CPM libraries | EPRI lattice codes | **`NotPorted`** stub | none |
| **PLOTR** | VIEWR input describing 2-D/3-D plots of ENDF/PENDF/GENDF data | plotting | **`NotPorted`** stub | none |
| **VIEWR** | PostScript from plot commands (also used by COVR and DTFR) | plotting | **`NotPorted`** stub | none |

**A correction made while writing this page.** The crate's `lib.rs` listed
WIMSR among the `NotPorted` stubs. It was ported and verified on 2026-09-11;
only its card-deck `run()` is still `NotPorted` (callers build a `WimsrInput`).
The comment now says so, with a strike-through.

The five stubs are deliberate: OUTRAM PARK does not target those codes, and a
stub returns `NjoyError::NotPorted("matxsr")` rather than a plausible-looking
file. In this workspace plotting is done by the demos and egui apps, not
PostScript. They stay visible rows so nobody mistakes the absence for a
capability. The NJOY2016 manual documents each (§MATXSR, §CCCCR, §POWR,
§PLOTR, §VIEWR of LA-UR-17-20093).

## WIMSR in a little more depth

WIMS needs, per material and group, absorption, ν σ_f, transport, a P0 (and
optionally P1) scattering matrix and, for resonance materials, **resonance
integrals as a function of temperature and background cross section**, the
deterministic counterpart of rung 4's probability tables. The port's
structure follows `wimsr.f90` one subroutine per file:
