## The question

[Rung 8](./errorr.md) asked what a file must contain for a Monte Carlo code to
run without the ENDF tape. **What is in an ACE file, and how do we know this
crate writes the same one NJOY does?**

## The shortest answer

An ACE ("A Compact ENDF") table is everything a continuous-energy code needs
for one nuclide at one temperature, already processed: a header (ZAID, atomic
weight ratio, temperature), two small integer arrays **NXS** (sizes) and
**JXS** (32 locators), and one long real array **XSS** with every block laid
end to end. The blocks follow the rungs of this book:

| ACE block (JXS) | contents | built from |
|---|---|---|
| ESZ (1) | union energy grid; total, absorption, elastic, heating | RECONR + BROADR (rungs 2–3), HEATR (rung 6) |
| NU (2), DNU/BDD | ν̄ prompt and total; delayed ν̄ and precursor groups | MF=1/452/455/456 |
| MTR/LQR/TYR/LSIG/SIG (3–7) | every reaction's σ(E), Q and yield | RECONR + BROADR |
| LAND/AND (8–9) | angular distributions | MF=4/6 |
| LDLW/DLW (10–11) | secondary energy distributions (ACE laws 3, 4, 44, 61, …) | MF=5/6 |
| GPD, photon blocks (12–19) | photon production | MF=12–15 |
| UNR (23) | probability tables | PURR (rung 4) |

ACER writes five classes: continuous-energy `c` (`acefc.f90`), thermal `t`
(`aceth.f90`, rung 5), dosimetry `y`, photo-atomic `p` and photo-nuclear `u`.
This crate writes all five, and reads all five back.

## The formula

None new: ACER is bookkeeping. Its one equation is the layout rule, and every
consumer depends on it:

```text
block k starts at XSS[ JXS(k) ]     (1-based; JXS(k) = 0 means the block is absent)
```

That makes **byte-level comparison** the natural check. A wrong count anywhere
moves every later locator, so a value comparison at a tolerance can pass on a
broken file while a word-for-word comparison cannot.

## The checks

**1. Four NJOY2016 ACE tables reproduced in every word.** Record
[`ace_block_parity_2026_09_26.md`](https://github.com/theodoreOnzGit/outram-park-backend/blob/@@COMMIT@@/crates/njoy-outram-park-fork/verification_and_validation/ace_block_parity/ace_block_parity_2026_09_26.md)
(2026-09-26), against the tables in the `reference-data/ace` submodule, built
by NJOY2016 `ac5adf5` with the same decks:

| table | XSS words | result |
|---|---|---|
| U-234, 293.6 K, RECONR → BROADR → PURR(20, 64) → ACER | 449 695 | identical, every block |
| U-238, 293.6 K, same deck | 6 247 445 | identical, every block |
| U-235, 293.6 K, same deck | 6 712 632 | identical, every block |
| U-235, 0 K, RECONR → ACER | 15 616 079 | identical, every block |

There is no tolerance in that claim, including PURR's bands (rung 4) and the
charged-particle blocks. The other classes have their own byte-level records:
photo-atomic (byte-identical Type 1 on a synthetic Z = 6 tape; 71 781 of
71 807 words at print precision on real uranium), dosimetry (byte-identical on
H-1 and Mn-55), photo-nuclear (byte for byte on a synthetic tape, 556 781
bytes), thermal in all three `IFENG` forms (point counts identical to NJOY's on
Al-27 and graphite). Records: `verification_and_validation/acer_*_vs_njoy2016.md`.

**2. The same transport code on both libraries.** From
[`five_route_keff_2026_09_29.md`](https://github.com/theodoreOnzGit/outram-park-backend/blob/@@COMMIT@@/crates/outram-mc-libs/verification_and_validation/icsbep/five_route_keff_2026_09_29.md)
("after the OpenMC-parity audit", 2026-09-30; 32 seeds per cell, ±1 sem):
OpenMC on this crate's ACE (route 2) against OpenMC on NJOY2016's (route 1):
Godiva **+0 ± 29 pcm**, Jemima **+0 ± 25 pcm**, identical seed for seed;
HST-009 +41 ± 38; LCT-008 +4 ± 9. And `outram-mc` reading this crate's ACE
(route 5) against reading NJOY2016's (route 3): identical on Godiva and Jemima,
+50 ± 32 pcm on HST-009 and +16 ± 8 pcm on LCT-008 (differences of the
recorded means, sems combined in quadrature by this page, unpaired; the
thermal table is the only data difference).
The table and its caveats are on [rung 0](./where-sigma-comes-from.md).

**What was wrong on the way** (the block-parity record's list, abridged): the
ENDF float parser rounded twice (rung 1); two independent Type-1 writers had
drifted apart in three header fields, found only by a byte comparison and
fixed by deleting one; a "deliberate divergence" on MT=18 over the partial
fission chances turned out to be visible in NJOY's MTR block and was reverted
to upstream's.

**Two places the port deliberately does not follow NJOY**, both recorded in
the crate's `CLAUDE.md`: it **refuses** to write a 0 K dosimetry table (NJOY
writes one with ZAID `0.00y` and AWR 0), and it **reads** mcnpx-format
dosimetry and thermal files that NJOY's own reader cannot dispatch.

All of this is **verification**: this crate's ACE is NJOY2016's ACE. Whether
`k` matches an experiment is the Monte Carlo track's question; the same record
gives Godiva on route 4 (this crate's ENDF route, read directly) as
**0.99948 ± 0.00027** against the benchmark's 1.0000 ± 0.0010.
