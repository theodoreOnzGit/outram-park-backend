## 2. ACER `iopt = 7` (task B, part 1: the edited ACE file and the directory)

Ported: `acefix` (Type 1, non-MCNPX, classes `c h o r s a`), `aceout`'s header
and directory line, and `change` (`acefc.f90:13091-13965`, with `acecm`'s
`advance_to_locator`/`typen`) in `src/acer/acefix.rs` and
`src/acer/acefix_change.rs`. The deck driver runs `iopt = 7`; it also writes
the directory unit for `iopt = 1` (it was left unwritten).

Why `change` had to be ported: the file does not record which XSS words are
integers. NJOY's `iopt = 1` output prints some charged-particle-block words as
reals that `change` prints as integers (deck 24: `-6.33700000000E+03` in unit
31, `-6337` in unit 34), so the check file is not a copy of its input.
Padding words that `advance_to_locator` skips are printed as integers.

Second finding, in the shared writer: Fortran `E20.11` of an exponent of three
digits drops the `E` (`1.15510000000-117`); `fortran_e` printed
`1.15510000000E-117`. That differed from NJOY in unit 31 as well (deck 62).

Prediction (written before the runs): the check file is the input with the
comment replaced (`suff = -1` keeps the ZAID) and every word reprinted by
`change`; the directory line is one `xsdir` line. Both identical where the
`iopt = 1` table is.
