# Photo-nuclear ACE (`acer iopt = 5`) vs NJOY2016

**Date:** 2026-09-22 · **Port:** `src/acer/photonuclear/` · **Oracle:**
NJOY2016 2016.79, rebuilt from `upstream_source/NJOY2016` on this machine
(`cmake -S . -B build2 -DCMAKE_BUILD_TYPE=Release && cmake --build build2`,
gfortran 13.3.0, clean 100 % build).

## The tape problem, and what was done about it

`reference-data/endf/` holds no photo-nuclear sublibrary tape. The IAEA NDS
host this crate's `acquire` module downloads from, `www-nds.iaea.org`, is
**blocked by the execution environment's network policy** — the agent proxy
answers `403` to CONNECT, recorded in its own status endpoint as
`connect_rejected … host: www-nds.iaea.org:443`. So no real tape could be
fetched, and the environment's rules say to report a blocked host rather than
route around it.

Verification therefore uses **`photonuc-synthetic-Z6.endf`**, generated by the
committed script beside it and fed to **both** codes. This repository already
does exactly this for `photoat-synthetic-Z6.endf` and
`synthetic-caseb-lfw1.endf`. It verifies that the two codes agree on identical
input — which is the whole content of a code-to-code comparison — and it
supports **no** claim about physics. Every number in it is an analytic shape.

What it exercises: `NSUB = 0`, MF=3/MT=5 (the LANL single-non-elastic form
that supplies the ACE energy grid, `acepn.f90:207-227`), and MF=6/MT=5 with
four emitted particles, each LAW=1 / LANG=1 / NA=0.

NJOY input:

```text
acer / 20 21 0 24 25 / 5 1 1 .00 / 'z6 photonuclear' / 600 0.
```

with the tape on both units — a photo-nuclear evaluation has no resonances, so
its own linear MF=3 serves as the PENDF. Output: a 27 453-word `6012.00u`
table, 556 781 bytes, committed as
`reference-data/acer/z6_photonuclear_njoy2016.ace`.

## Results — read side (2026-09-22)

| check | result |
|---|---|
| class from the ZAID | `u` — **the last class letter to be read from a real file** |
| `NXS` recovered | `LXS` 27 453, `ZA` 6012, `NES` 38, `NTR` 1, `NTYPE` 4, `NEIXS` 12, `IZ` 6, `IA` 12 |
| layout walk | 4 emitted particles (IPT 1, 2, 9, 34 — n, γ, p, α), ends **exactly** at word 27 453 |
| read-then-write, 556 781 bytes | **byte-identical** |

The byte-identical round trip is the load-bearing result. A photo-nuclear
table's integer/real split is stored nowhere, so reproducing NJOY's bytes means
walking the **whole** per-particle structure the way `phnout` does
(`acepn.f90:2504-2780`): `PXS`, `PHN`, `MTRP`, `TYRP`, `LSIGP`/`SIGP` with its
MF=12/13 branch, `LANDP`/`ANDP` with its equiprobable-versus-tabulated
sub-branch, and `LDLWP`/`DLWP` with law bodies 4, 44, 61, 7/9 and 33 —
including the two levels of locator chasing law 61 needs. One wrong count or
locator anywhere in 27 453 words changes a byte. `src/acer/photonuclear/layout.rs`
is that walk.

It is also a **validator**: a table whose counts do not add up walks off its
own end and is reported, rather than producing a plausible answer.
`a_corrupt_count_is_refused_rather_than_walked_past` pins that.

## Results — build side

**Not yet.** `acephn` (`acepn.f90:27-1853`) is 1 826 lines and is being ported
incrementally. Nothing is claimed for it here until it produces a table to
compare, and the gates in `tests/acer_photonuclear_vs_njoy2016.rs` currently
cover the read side alone — deliberately, so this record cannot be read as
saying more than has been measured.

## Not covered

- **No real photo-nuclear evaluation has been processed**, only the synthetic
  tape, for the reason above. Whether a production IAEA/ENDF photo-nuclear
  file exercises branches this tape does not is **unknown and untested** —
  in particular MF=4-only angular data, MT=18 fission with its MF=1/452
  nubar, discrete MT=600-849 charged-particle levels, and the `ielas = 1`
  elastic path (`ELS` is `0` on this tape and `NON` therefore aliases `TOT`).
- **Nothing here is validation.** It says this port reads what NJOY2016 writes.
