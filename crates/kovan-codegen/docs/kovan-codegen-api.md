# Module `kovan_codegen`

# kovan-codegen

A **deterministic** engineering-code generation framework. It emits
implementations of **known** algorithms, engineering patterns, and numerical
methods — it does **not** generate speculative or arbitrary software, and it
is **not** an AI coding assistant. See docs/kovan.md § "KOVAN Codegen".

## Priority order

```text
Correctness > Traceability > Maintainability > Performance > Convenience
```

## How generation works

Every generated method's source lives in a small, human-readable template
file under `src/<family>/templates/`. Each template file is used **two
ways**:

* returned verbatim by [`generate`] (via `include_str!`), and
* compiled into that family's `reference` module (via `include!`),

so the crate's own tests execute the *exact bytes* [`generate`] emits. This
is the verification link: the numerical-correctness tests (e.g. "the
generated Newton finder recovers sqrt(2)", "the generated RK4 stepper
integrates `dy/dt = y` to `e`") validate the emitted source itself, not a
separate copy. Generation is deterministic — the same [`Method`] always
yields byte-identical output — because the templates are compile-time
constants (no formatting, no randomness, no I/O).

## Why string templates, not proc-macros

KOVAN is offline- and Android-first. String templating with `include_str!`
is pure `core`/`std`, cross-compiles to `aarch64-linux-android` with no
native dependency, and keeps every generated artifact inspectable and
diffable. Procedural macros (`syn`/`quote`) are *scaffolded* in
[`macros_support`] but not used for the numerical-method path — see
`DECISIONS.md`.

## Modules

* [`root_finding`], [`linear`], [`nonlinear`], [`ode`], [`pde`] — the

### Functions

#### Function `lu_solve`

Solve the dense linear system `A x = b` by **LU decomposition with partial
pivoting** (Gaussian elimination).

The `n x n` matrix `A` is reduced to upper-triangular form in a working copy
using row interchanges that place the largest-magnitude available pivot on
the diagonal (partial pivoting, for numerical stability). The right-hand side
is transformed in lockstep, then the triangular system is resolved by back
substitution. This is equivalent to forming `P A = L U` and solving
`L U x = P b`. Cost is `O(n^3)`.

# Arguments
* `a` — row-major `n x n` coefficient matrix (`a[i][j]` is row `i`, col `j`).
* `b` — right-hand-side vector of length `n`.

# Returns
`Some(x)` with the solution vector, or `None` if the dimensions are
inconsistent or the matrix is singular (a zero pivot column is encountered).

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → Linear
Solvers"). Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn lu_solve(a: &[Vec<f64>], b: &[f64]) -> Option<Vec<f64>> { /* ... */ }
```

## Module `macros_support`

Scaffolding for the macro-based half of KOVAN codegen (docs/kovan.md §

## What is fully realised vs scaffolded

* **Declarative macros** (`macro_rules!`) — fully realised. They run entirely
  at compile time with zero dependencies, so they are the Android-first,
  offline-friendly workhorse. [`crate::kovan_fixed_point`] is a working, tested
  example (defined at the crate root by `#[macro_export]`).
* **Derive / attribute / procedural macros** — *scaffolded only*. A
  procedural macro must live in its own crate compiled with
  `proc-macro = true` (and pulls in `syn` / `quote` / `proc-macro2`), so it
  cannot be defined inside this library crate. [`generate_macro_scaffold`]
  therefore emits a documented skeleton (the separate-crate `Cargo.toml`
  stanza plus the macro entry point) for a human to drop into a companion
  `kovan-codegen-macros` crate. See `DECISIONS.md`.
* **`build.rs` generation** — *scaffolded only*. [`generate_macro_scaffold`]
  emits a `build.rs` skeleton that writes a generated `.rs` file into
  `OUT_DIR` for `include!`, the standard offline codegen pattern.

### Functions

#### Function `fixed_point`

Solve the scalar equation `x = g(x)` by **fixed-point iteration**.

Starting from `x0`, repeatedly applies `x_{k+1} = g(x_k)`. The iteration
converges to a fixed point `x* = g(x*)` whenever `g` is a contraction near
`x*` (i.e. `|g'(x*)| < 1`); the smaller `|g'|`, the faster the (linear)
convergence. If `|g'| >= 1` the iteration may diverge — reformulate the
equation so the fixed-point map is contractive.

# Arguments
* `g`        — the fixed-point map.
* `x0`       — initial guess.
* `tol`      — absolute tolerance: stop when `|g(x) - x| <= tol`.
* `max_iter` — iteration cap.

# Returns
`Some(x)` on convergence, or `None` if `max_iter` is exceeded.

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → Nonlinear
Solvers"). Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn fixed_point<G>(g: G, x0: f64, tol: f64, max_iter: usize) -> Option<f64>
where
    G: Fn(f64) -> f64 { /* ... */ }
```

### Functions

#### Function `newton_system`

Solve the vector equation `F(x) = 0` for `x` in `R^n` by **Newton's method
for systems**.

Each iteration linearises `F` at `x_k` and solves the Jacobian system for the
Newton step: `J(x_k) delta = -F(x_k)`, then updates `x_{k+1} = x_k + delta`.
Near a simple root with a nonsingular Jacobian it converges quadratically.
The linear solve uses Gaussian elimination with partial pivoting (embedded
below so the template is self-contained).

# Arguments
* `f`        — residual map: `f(x)` returns the length-`n` vector `F(x)`.
* `jac`      — Jacobian map: `jac(x)` returns the `n x n` matrix `J[i][j] = dF_i / dx_j`.
* `x0`       — initial guess (its length fixes `n`).
* `tol`      — absolute tolerance on the Euclidean residual norm `||F(x)||`.
* `max_iter` — iteration cap.

# Returns
`Some(x)` on convergence, or `None` if a Jacobian solve fails (singular) or
`max_iter` is exceeded.

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → Nonlinear
Solvers"). Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn newton_system<F, J>(f: F, jac: J, x0: Vec<f64>, tol: f64, max_iter: usize) -> Option<Vec<f64>>
where
    F: Fn(&[f64]) -> Vec<f64>,
    J: Fn(&[f64]) -> Vec<Vec<f64>> { /* ... */ }
```

### Functions

#### Function `backward_euler_step`

One step of the implicit **backward (implicit) Euler** method for
`dy/dt = f(t, y)`.

Backward Euler is defined by `y_{n+1} = y_n + h f(t_{n+1}, y_{n+1})`, an
implicit equation in the unknown `y_{n+1}`. This template solves that
equation with a Newton iteration whose derivative is obtained by a
forward finite difference (so the caller need not supply `df/dy`). Backward
Euler is A-stable — it stays bounded for stiff decay problems at any step
size — and first-order accurate (global error `O(h)`).

# Arguments
* `f` — right-hand side `f(t, y)`.
* `t`, `y` — current time and state.
* `h` — step size.

# Returns
`Some(y_{n+1})` on convergence of the inner Newton solve, or `None` if the
finite-difference derivative underflows or the inner solve fails to converge.

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → ODE
Solvers"). Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn backward_euler_step<F>(f: &F, t: f64, y: f64, h: f64) -> Option<f64>
where
    F: Fn(f64, f64) -> f64 { /* ... */ }
```

### Functions

#### Function `rms_residual_norm`

Root-mean-square (RMS) norm of a residual vector, the usual scalar
convergence measure for iterative solvers:
`sqrt( (1/n) * sum_i r_i^2 )`.

Dividing by `n` (rather than the plain Euclidean 2-norm) makes the value
grid-size independent, so a single tolerance carries across mesh
refinements. An empty slice returns `0.0`.

Generated by kovan-codegen (docs/kovan.md § "Engineering Pattern Library").
Deterministic template; depends only on `core`/`std` `f64`.

### Functions

#### Function `under_relaxation_update`

Under-/over-relaxation update, the ubiquitous stabiliser for fixed-point and
segregated (e.g. SIMPLE-family) iterations:
`x_new = x_old + alpha * (x_star - x_old)`.

`x_star` is the freshly computed (unrelaxed) value and `alpha` is the
relaxation factor: `0 < alpha < 1` under-relaxes (damps oscillation, the
common case), `alpha = 1` applies the raw update, and `1 < alpha < 2`
over-relaxes to accelerate a stable iteration.

Generated by kovan-codegen (docs/kovan.md § "Engineering Pattern Library").
Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn under_relaxation_update(x_old: f64, x_star: f64, alpha: f64) -> f64 { /* ... */ }
```

### Functions

#### Function `relative_change`

Relative change between successive iterates, a scale-free convergence
criterion: `|new - old| / max(|new|, floor)`.

The `floor` guards against division by zero when the solution passes through
zero (pass a small positive number such as `1e-30`); it also caps the
relative change when `|new|` is smaller than `floor`. Use it as
`if relative_change(new, old, 1e-30) < tol { break; }`.

Generated by kovan-codegen (docs/kovan.md § "Engineering Pattern Library").
Deterministic template; depends only on `core`/`std` `f64`.

```rust
pub fn relative_change(new: f64, old: f64, floor: f64) -> f64 { /* ... */ }
```

#### Function `solve_poisson_1d`

Solve the 1-D Poisson equation `-u''(x) = s(x)` on `[x0, x1]` with Dirichlet
boundary conditions by **second-order central finite differences** on a
uniform grid, resolving the resulting tridiagonal system with the **Thomas
algorithm** (`O(n)`).

The domain is split into `n_cells` equal intervals, giving `n_cells + 1`
nodes at spacing `dx = (x1 - x0) / n_cells`. Interior nodes use the standard
stencil `(-u_{i-1} + 2 u_i - u_{i+1}) / dx^2 = s(x_i)`; the two boundary
nodes are pinned to `u_left` and `u_right`. The scheme is second-order
accurate (`O(dx^2)`).

# Arguments
* `x0`, `x1`   — domain endpoints (`x1 > x0`).
* `n_cells`    — number of cells (`>= 2`); yields `n_cells + 1` nodes.
* `source`     — source term `s(x)` (the right-hand side of `-u'' = s`).
* `u_left`     — Dirichlet value at `x0`.
* `u_right`    — Dirichlet value at `x1`.

# Returns
`Some((xs, us))` with the node coordinates and the solution values, or
`None` if `n_cells < 2` or `x1 <= x0`.

Infrastructure"). Deterministic template; depends only on `core`/`std` `f64`.

### Functions

#### Function `bisection`

Find a root of `f` in the bracket `[a, b]` by **bisection**.

Bisection repeatedly halves a bracket `[a, b]` on which `f` changes sign
(`f(a) * f(b) <= 0`), keeping the sub-half that still brackets a root. It is
unconditionally convergent for a continuous `f` with a sign change and
converges linearly: the bracket width halves each iteration, so after `n`
steps the root is known to within `(b - a) / 2^n`.

# Arguments
* `f`        — continuous function whose root is sought.
* `a`, `b`   — bracket endpoints; **must** satisfy `f(a) * f(b) <= 0`.
* `tol`      — absolute tolerance on the bracket half-width (stop when the half-width is at or below `tol`).
* `max_iter` — hard cap on iterations.

# Returns
`Some(root)` (the final bracket midpoint) if a sign change is present and the
tolerance is met within `max_iter` steps, otherwise `None` (invalid bracket
or non-convergence).

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → Root
Finding"). Deterministic template; depends only on `core`/`std` `f64`.

#### Function `regula_falsi`

Find a root of `f` in `[a, b]` by the **regula falsi** (false-position)
method.

Like bisection it keeps a sign-changing bracket `[a, b]`, but instead of the
midpoint it takes the x-intercept of the secant line through the endpoints:
`c = b - f(b) (b - a) / (f(b) - f(a))`. It always retains a bracket (so it is
robust like bisection) and is usually faster, though on strongly convex or
concave functions one endpoint can stagnate — the Illinois and Pegasus
variants cure that stagnation (catalogued but not yet generated).

# Arguments
* `f`        — continuous function whose root is sought.
* `a`, `b`   — bracket endpoints; **must** satisfy `f(a) * f(b) <= 0`.
* `tol`      — absolute tolerance: stop when `|f(c)| <= tol`.
* `max_iter` — iteration cap.

# Returns
`Some(root)` on convergence, otherwise `None` (invalid bracket, degenerate
secant, or non-convergence).

Finding"). Deterministic template; depends only on `core`/`std` `f64`.

### Functions

#### Function `secant`

Find a root of `f` by the **secant** method.

The secant method approximates Newton's derivative with a finite difference
over the two most recent iterates:
`x_{k+1} = x_k - f(x_k) (x_k - x_{k-1}) / (f(x_k) - f(x_{k-1}))`.
It needs no analytic derivative and converges superlinearly (order about
1.618, the golden ratio) near a simple root, but — unlike bisection — does
not maintain a bracket and can diverge.

# Arguments
* `f`        — function whose root is sought.
* `x0`, `x1` — two distinct initial iterates.
* `tol`      — absolute tolerance: stop when `|f(x)| <= tol` or the step is at or below `tol`.
* `max_iter` — iteration cap.

# Returns
`Some(root)` on convergence, or `None` if the secant denominator underflows
(`|f(x_k) - f(x_{k-1})| < 1e-300`) or `max_iter` is exceeded.

Generated by kovan-codegen (docs/kovan.md § "Numerical Methods → Root
Finding"). Deterministic template; depends only on `core`/`std` `f64`.

### Functions

#### Function `newton_raphson`

Find a root of `f` by the **Newton–Raphson** method.

Newton's method linearises `f` at the current iterate and steps to that
linear model's root: `x_{k+1} = x_k - f(x_k) / f'(x_k)`. Near a simple root
it converges quadratically (the number of correct digits roughly doubles
each step). It requires the analytic derivative `df` and a starting guess
`x0`; it may diverge if `x0` is far from a root or if `f'` vanishes on the
iteration path.

# Arguments
* `f`        — function whose root is sought.
* `df`       — its derivative `f'`.
* `x0`       — initial guess.
* `tol`      — absolute tolerance: stop when `|f(x)| <= tol` or the Newton step magnitude is at or below `tol`.
* `max_iter` — iteration cap.

# Returns
`Some(root)` on convergence, or `None` if the derivative underflows
(`|f'| < 1e-300`, which would divide by zero) or `max_iter` is exceeded.

### Functions

#### Function `brent`

Find a root of `f` in `[a, b]` by **Brent's** method.

Brent's method combines the guaranteed convergence of bisection with the
speed of the secant method and inverse quadratic interpolation. It keeps a
bracket `[a, b]` with `f(a) * f(b) <= 0` and, at each step, attempts an
interpolation step, falling back to a bisection step whenever the interpolant
would leave the bracket or fail to shrink it fast enough. It converges
superlinearly without ever losing the bracket. This is the classic Brent
(1973) / `zeroin` formulation.

# Arguments
* `f`        — continuous function whose root is sought.
* `a`, `b`   — bracket endpoints; **must** satisfy `f(a) * f(b) <= 0`.
* `tol`      — absolute tolerance on `x`.
* `max_iter` — iteration cap.

# Returns
`Some(root)` on convergence, otherwise `None` (invalid bracket or
non-convergence).

## Functions

### Function `generate`

Generate Rust source implementing the given [`Method`].

Returns compilable, `///`-documented Rust source for the requested method,
using plain `f64` numerical kernels (these are generic math templates, so
they are intentionally `uom`-agnostic). The output contains no `unsafe`, no
trait-object dispatch, and no external-crate dependencies, so it drops into
any crate — including Android targets.

Generation is deterministic: calling this twice with the same [`Method`]
yields byte-identical strings.

# Errors
[`CodegenError::Unimplemented`] for catalogue entries that are named but not
yet backed by a template (e.g. GMRES, Dormand–Prince, Broyden). The payload
identifies the specific method.

# Examples
```
use kovan_codegen::{generate, Method, OdeSolver};
let src = generate(Method::Ode(OdeSolver::Rk4)).unwrap();
assert!(src.contains("pub fn rk4_step"));
```

```

### Function `generate_artifact`

Generate a [`Method`] and package it as a [`GeneratedArtifact`] provenance
record — the "Correlation → Implementation" link of the KOVAN integration
vision (`docs/kovan.md`, "Integration Vision").

The returned artifact carries the emitted source plus the (optional)
[`GeneratedArtifact::correlation_id`] and [`GeneratedArtifact::source_document_id`]
so a generated kernel can be traced back to the correlation and paper it
implements. Pass `None` for either when generating a bare method with no
literature link. `method` is recorded as its `Debug` label (e.g.
`"Ode(Rk4)"`), which is stable and deterministic.

# Errors
Propagates [`CodegenError::Unimplemented`] from [`generate`] for catalogue
entries that are named but not yet backed by a template.

# Examples
```
use kovan_codegen::{generate_artifact, Method, OdeSolver};
let art = generate_artifact(
    Method::Ode(OdeSolver::Rk4),
    Some("corr-rk4".to_string()),
    None,
)
.unwrap();
assert_eq!(art.method, "Ode(Rk4)");
assert!(art.source.contains("pub fn rk4_step"));
assert_eq!(art.correlation_id.as_deref(), Some("corr-rk4"));
```

## Macros

### Macro `kovan_fixed_point`

**Attributes:**

- `MacroExport`

Declarative fixed-point loop, expanded at compile time (no dependencies).

`kovan_fixed_point!(x0, tol, max_iter, g)` iterates `x = g(x)` from `x0`
until `|g(x) - x| <= tol` or `max_iter` iterations elapse, evaluating to
`Option<f64>` (`Some(root)` on convergence, `None` otherwise). This is the
canonical example of KOVAN's declarative-macro strategy: pure compile-time
expansion, zero dependencies, Android/offline friendly.

```rust
pub macro_rules! kovan_fixed_point {
    /* macro_rules! kovan_fixed_point {
    ($x0:expr, $tol:expr, $max_iter:expr, $g:expr) => { ... };
} */
}
```
