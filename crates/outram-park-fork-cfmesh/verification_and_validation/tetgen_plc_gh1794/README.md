# TetGen port, stage 5: the whole `-p` route against the unmodified upstream binary (gh:#1794)

> AI-assisted draft, untrusted until human-reviewed (`RESPONSIBLE_USE.md`).
> For education, research and V&V only.

Epic gh:#1789. Stage 5 ports what TetGen 1.6.0's `tetrahedralize()`
(`tetgen.cxx:36120`) runs for `-p` and `-pY` after `recoverboundary()`,
without `-q`, through to the output files. `tetgen::tetrahedralize_plc` now
runs the whole route.

- **`src/tetgen/carve.rs`**: `carveholes` (unprotected hull tets, volume
  holes located by `randomsample` + `locate`, regions with `-A`, the new
  hull, subface and segment removal, exterior vertices made unused, the
  attribute flood fill, the hull-sliver `lawsonflip3d`),
  `suppresssteinerpoints`, `suppressbdrysteinerpoint`, the general
  `getvertexstar` (`getvertexstar_with`), `enqueuetetrahedron`.
- **`src/tetgen/optimize.rs`**: `get_tetqual` (both forms), `get_tet`, the
  64-bucket bad-tet queue (`enqueue_badtet`, `top_badtet`,
  `dequeue_badtet`), `improve_mesh`, `repair_badqual_tets`, `repair_tet`,
  `flip_edge_to_improve`, `add_steinerpt_to_repair`, `smooth_vertices`,
  `move_vertex`, `get_laplacian_center`, `get_surf_laplacian_center`,
  `get_seg_laplacian_center`.
- **`src/tetgen/output.rs`**: `TetgenOutput` (`outnodes`, `outelements`,
  `outsubfaces`, `outsubsegments` with `-z`, the point, facet and segment
  markers, the `-A` attribute), its four file writers with C's `%.17g`
  (`fmt_g17`), the point-marker re-indexing of `jettisonnodes`, and
  `to_volume_mesh`.
- **`src/tetgen/tetrahedralize.rs`**: `TetgenMesh::finish_plc` (the driver
  sequence) and the `Switches` builder (`-p`, `-z`, `-Y`, `-A`, `-M`, `-J`,
  `-X`, `-d`).
- Extended, behaviour unchanged on the stage 1-4 paths: `flip.rs`
  (`remove_large_angle` in `checkflipeligibility`, the `chkencflag & 4`
  queue in `flip23` / `flip32` / `flip41`, the `-A` attribute copies),
  `steiner.rs` (`insertpoint`'s `chkencflag & 4` and attribute
  inheritance), `mesh.rs` (switches and fields; `maketetrahedron` clears
  `[10]` as upstream does, struck-through comment there).

**Does plain `-p` run `improve_mesh`?** Yes: `tetrahedralize()` calls it
under `if (b->plc || b->quality)`. And `smooth_vertices` runs under `-p`
whenever Steiner points are left in facets or the volume (`smooth_maxiter`
defaults to 7). Both are ported here, so stage 6 (#1795) only adds
`delaunayrefinement` and `-q` / `-a`.

**The switch post-processing matters.** `parse_commandline` sets
`optmaxdihedral` to 179.9 when `-q` is off (`tetgen.cxx:3744`; the struct
default is 177). The first port run used 177 and 32 of 192 files differed
(`improve_mesh` queued tetrahedra upstream does not). `finish_plc` applies
the rule.

## Methodology

- **Reference.** The unmodified upstream binary
  (`/home/user/tetgen-upstream/build/tetgen`, libigl/tetgen `e05aca7df74e`,
  x86_64, glibc 2.39), run as `tetgen -<sw> <case>` from `PATH` so that the
  `# Generated by tetgen -<sw> <case> ` line is reproducible, **without
  `-Q`** (stage 4: upstream's quiet mode skips some error exits).
- **Runs.** 21 cases x {`-pz`, `-pzY`}, plus {`-pzA`, `-pzAY`} on the three
  cases with holes or regions (`example`, `box_hole`, `fuel_pin_regions`):
  48 runs, 192 files.
- **Cases.** Stage 3's 13 and stage 4's 6 inputs, and two new ones written
  once by a scratch script from `fuel_channel.smesh` (Mesh Studio's fuel
  pin in a channel, size 2): `fuel_pin_hole.smesh` closes the pin with two
  32-gon caps (markers 5, 6) and makes it a **volume hole** (hole point
  (0, 0, 2)); `fuel_pin_regions.smesh` has the same closed pin and **two
  regions** (pin, attribute 10; coolant, attribute 20). The Mesh Studio
  surfaces at size 2 are `pipe`, `fuel_channel` (its pin is open at both
  ends, so carving removes it as exterior) and `pebble` (the pebble is a
  closed internal surface: a second region, meshed). `box_hole` has a
  volume hole inside the box; `example` has two regions.
- **Pass criterion.** Every `.node`, `.ele`, `.face`, `.edge` equal byte for
  byte; and the 64 stage 5 reach counters `tg5` equal the port's
  `TetgenMesh::reach5`. No tolerance.
- **Reach counters.** `stage5_reach.patch` (apply after stage 4's
  `recoverboundary_dump.patch`) adds `tg5[]` (written to `TG_REACH5`) and
  dump hooks (`TG_DUMP5C`, `5S`, `5D`, `5M`, `5I`, `5J`: stage 4's dump
  after `carveholes`, the suppression, `recoverdelaunay`, smoothing,
  `improve_mesh`, `jettisonnodes`, then exit; used to localise the one
  divergence found). Without the variables the instrumented build writes
  the same 192 files as the unmodified binary (checked with `cmp`).
- **Test.** `tests/tetgen_plc_vs_upstream.rs`, reading committed files
  only: the inputs (stage 3, stage 4 and `test_data/tetgen_plc/`) and the
  192 reference files plus 48 reach files (`test_data/tetgen_plc/`, gzip,
  1.1 MB).

### Regenerating

```bash
S=<scratch>/tetgen_stage5; mkdir -p $S/src $S/cases $S/ref
cp <tetgen-clone>/{tetgen.cxx,tetgen.h,predicates.cxx} $S/src/
cd $S/src && patch -p1 < <repo>/crates/outram-park-fork-cfmesh/verification_and_validation/tetgen_recoverboundary_gh1793/recoverboundary_dump.patch \
          && patch -p1 < <repo>/crates/outram-park-fork-cfmesh/verification_and_validation/tetgen_plc_gh1794/stage5_reach.patch
g++ -O0 -c predicates.cxx -o predicates.o
g++ -O2 -ffp-contract=off -o tetgen_dump tetgen.cxx predicates.o -lm
# inputs: gunzip test_data/tetgen_{meshsurface,recoverboundary,plc}/*.{poly,smesh,edge}.gz into $S/cases
cd $S/ref && for sw in pz pzY; do for f in $S/cases/*.poly $S/cases/*.smesh; do   # (not fin_crash)
  cp $f .; c=$(basename ${f%.*}); [ -f $S/cases/$c.edge ] && cp $S/cases/$c.edge .
  PATH=<tetgen-clone>/build:$PATH tetgen -$sw $(basename $f) > /dev/null
  for x in node ele face edge; do mv $c.1.$x $c.$sw.$x; done; done; done
# and -pzA, -pzAY on example, box_hole, fuel_pin_regions; reach files with
#   TG_REACH5=$c.$sw.reach5 $S/src/tetgen_dump -$sw <case>
for f in *.p*.* ; do gzip -n -9 -c $f > <repo>/crates/outram-park-fork-cfmesh/test_data/tetgen_plc/$f.gz; done
cargo test --release -p outram-park-fork-cfmesh --test tetgen_plc_vs_upstream -- --nocapture
```

**`improve_mesh` reach.** It runs on every case and finds no bad
tetrahedron on 32 of the 48 runs. On the others it repairs by flips
(`flip_edge_to_improve`, `removeedgebyflips` with `remove_large_angle` and
`unflip`): `pebble -pzY` 955 flips in 1 782 `repair_tet` calls, `sphere
-pzY` 540, `pebble -pz` 822; and by Steiner points
(`add_steinerpt_to_repair`, `insertpoint` with `chkencflag & 4`, Lawson
flips, then `get_laplacian_center` + `move_vertex`): `pebble -pzY` 16,
`facet_wall*` 3, `skew_segments` 8, `skew_points` 6, `sphere -pzY` 1. Both
sliver shapes are reached (`'S'` and `'T'`). **Not reached by any committed
case** (say so if you rely on them): the skinny-tetrahedron branch
(`eta > opt_max_edge_ratio`) and `create_a_shorter_edge` from improvement; a
failed `insertpoint` in `add_steinerpt_to_repair`;
`get_surf_laplacian_center` (no facet Steiner point survives to
`smooth_vertices`); `carveholes`' segment deletion; `lawsonflip3d`'s
hull-vertex removal (`removevertexbyflips` from the non-convex branch); a
successful `suppressbdrysteinerpoint` (`slit_box -pzY` calls it and it
fails, as upstream's does). `-YY`'s stop and `-d` are not compared.

**Times.** The port is about as fast as the binary: `pebble` 94 / 113 ms
(`-pz` / `-pzY`) against 127 / 132 ms for `tetgen -Q` (process start and
file writing included), `sphere` 85 / 99 against 132 / 112, `fuel_channel`
6 / 18 against 8 / 20. The whole test (48 runs, files rendered and compared)
takes under 1 s.

### Proving the test can fail

- `the_comparison_can_fail` (committed): `optmaxdihedral = 176` changes
  `pebble -pz`'s `.ele`.
- By hand (then restored): the bad-tet queue's bucket factor 64 changed to
  63 in `BadTetQueue::enqueue` made 15 of 192 files and several reach files
  differ (`facet_wall`, `skew_segments`, ...).

### Upstream-free checks (`plc_mesh_fills_the_domain`)

On every run: every tetrahedron positively oriented (exact
`orient3d < 0`); every boundary face of the tetrahedral mesh is a `.face`
triangle; the tetrahedra's volume equals the volume the PLC encloses net of
its holes to 1e-9 relative, the PLC volume computed from the input facets
alone (polygon regions by nesting, outward side by ray parity, divergence
theorem; internal facets and the hole shell named per case from how each
input was built). **Finding:** on `sphere -pz` the mesh encloses 3.394e-6
less than the PLC (4.158971 vs 4.158968): `carveholes`' `lawsonflip3d`
peels 534 hull slivers lying between boundary triangles of *different*
facets (the cospherical sphere soup) and flips those triangles, so the
boundary no longer lies exactly on the input facets. Upstream does the same
(the files are identical); the port records the peeled volume
(`TetgenMesh::hull_sliver_volume`, not upstream) and the check subtracts
it. The `VolumeMesh` export is closed (`validate`) with one cell per
tetrahedron.

## The `VolumeMesh` export and the images

`tetgen::to_volume_mesh(&TetgenOutput, names)` gives one cell per
tetrahedron in `.ele` order, internal faces where two tetrahedra share a
face, and boundary faces in one patch per facet marker (named from
`SurfaceRegions::names` when the PLC's markers are region indices), then
`renumber_mesh::upper_triangular`. Unit test
`tetgen::output::tests::to_volume_mesh_is_a_valid_upper_triangular_mesh`:
`pipeline::acceptable`, `check_upper_triangular`, the patches, volume 1.

Images (drawing rule), from `cargo run --release -p dhoby-ghaut --example

`to_volume_mesh`, then Mesh Studio's own section code (`outram_blender`'s
converters and `outram_foam_mesh::section::plane_section`). Each cut
tetrahedron is filled by its region attribute and outlined.

## Not ported (with why)

`-q` (`delaunayrefinement`), `-a` volume bounds, `-m`, `-R`
(`meshcoarsening`), `-i`, `-o2`, `-c` (`b->convex`), `-H` (hole mesh),
`-D` (CDT), `-B`, `-nn`, `-f`, `-e`, `-w`, point attributes: switches the
`-p` route here does not take. `skipped_facet_list` (self-intersecting
input) returns `TetgenError::SelfIntersection` where upstream writes the
files and stops; `-YY` with boundary Steiner points returns `InternalError`
where upstream writes and stops (code 200). `insertpoint`'s `smlenflag`
only fills `ivf.smlen` / `parentpt`, which `add_steinerpt_to_repair` does
not read. The volume bound copies of `-a` in the flips are not ported.

## What stage 6 (gh:#1795) needs

`delaunayrefinement` (`repairencsegs`, `repairencfacs`, `repairbadtets`,
`get_steiner_on_segment`, `get_subface_ccent`, `check_encroachment`,
`locate_on_surface`, `locate_point_walk`), `insertpoint`'s `rejflag`,
`chkencflag & 1 / 2` queues (`enqueuesubface`), insertion radii and
`smlenflag`; the facet maps `create_a_shorter_edge` reads (built by `-q`);
`-a` volume bounds (`setvolumebound` in the flips, `carveholes`' region
volume); the `quality` switch, which also keeps `optmaxdihedral` at 177.
