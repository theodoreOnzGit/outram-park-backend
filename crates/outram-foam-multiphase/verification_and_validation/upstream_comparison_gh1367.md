# outram-foam-multiphase against upstream OpenFOAM (gh:#1367)

Differential comparison, one row of the issue at a time. Upstream is **ESI
OpenFOAM-v2506** (maintainer, 2026-11-12: "ESI preferred", because GeN-Foam is
compared against ESI later). Where a port file follows the Foundation line, the
Foundation text (`OpenFOAM-dev`, commit 852527377c7e, 2026-11-03) is also read.
Research, education and V&V only (`RESPONSIBLE_USE.md`).

## Which line each ported file follows

Every ported file's provenance header reads "Derived from OpenFOAM
(www.openfoam.com), Copyright 2004-2023 OpenFOAM Foundation", and the module
docs name `multiphaseEuler` and `incompressibleDriftFlux`, which are

(`applications/solvers/multiphase/`, `src/phaseSystemModels/`). The per-file
table at the end of this record is filled in as each file is read.

## Row 3: interfacial heat transfer K on a frozen field

### Method

`driver/heatTransferDump.C` evaluates upstream's `K()` expressions, transcribed
verbatim from the upstream `.C` files, on OpenFOAM `scalarField`s (the same
`Field` operators, `max`, `sqrt`, `cbrt`, `pow`, `sqr` that a `volScalarField`
expression calls). It does **not** call `heatTransferModels::RanzMarshall::K()`
itself: that needs a `phasePair`, which needs the whole phaseSystem library,
which is not built (disk). What is shared with upstream is the field algebra and
the libm; what is transcribed is the expression. Inputs are generated by a
fixed integer generator (splitmix64) that the Rust test reproduces and checks
against the committed input columns, so both sides see identical bits.

4096 cells; per cell `alpha_d`, `kappa_c`, `kappa_d`, `d`, `Re`, `Pr`;
`alpha_c = 1 - alpha_d`; one residual alpha, 1e-6. Four forced cells: `alpha_d =
0`, `alpha_d = 1`, `Re = 0`, `alpha_d = 1e-9` (below the residual).

### Predictions (written before the driver or the port was run)

- **P1 RanzMarshall, port vs ESI v2506.** Same algebra, same operation order
  (`6*max(ad,res)*kappa_c*Nu/sqr(d)`, `Nu = 2 + 0.6*sqrt(Re)*cbrt(Pr)`).
  `sqrt` is correctly rounded on both sides; `cbrt` is glibc on one side and
  PETIR on the other. Predicted: at least 99 % of cells bit-identical; worst
  relative difference at most 4e-16 (2 ulp); every difference traced to `cbrt`.
- **P2 sphericalHeatTransfer, port vs ESI v2506.** ESI reads
  `pair_.continuous().kappa()`; the port reads `kappa_d` (Foundation's text).
  Predicted: **0 % bit-identical**, and `K_port / K_ESI = kappa_d / kappa_c` to
  2e-16 in every cell. This is a structural difference, not round-off.
- **P3 sphericalHeatTransfer, port vs Foundation expression.** One multiply
  chain, no transcendental. Predicted: 4096 of 4096 bit-identical.
- **P4 Gunn, port vs Foundation expression.** ESI v2506 has no Gunn model, so
  Foundation is the only upstream. `pow(Re, 0.2)`, `pow(Re, 0.7)` and `cbrt`
  differ between glibc and PETIR. Predicted: at least 90 % bit-identical, worst
  relative difference at most 1e-15, every difference traced to `pow` or `cbrt`.
- **P5 forced cells.** `alpha_d = 0` and `alpha_d = 1e-9` give the residual
  branch and agree bit for bit in P1, P3 and P4.

### First divergent operation

Upstream's intermediates were dumped too (`sqrtRe`, `cbrtPr`, `powRe02`,
`powRe07`, `Nu_*`):

| Operation | Bit-identical to glibc |
|---|---|
| `sqrt(Re)` | 4096 / 4096 |
| `cbrt(Pr)` | **2159 / 4096**, worst 4.4e-16 |
| `pow(Re, 0.2)` | 4090 / 4096, worst 2.2e-16 |
| `pow(Re, 0.7)` | 4093 / 4096, worst 1.4e-16 |

Feeding upstream's own `sqrt` and `cbrt` into the `Nu` expression reproduces
upstream's `Nu` in 4096 of 4096 cells, so the algebra and operation order are
identical. Every differing `K` cell is a cell where a `cbrt` or `pow`
differs (asserted by the tests).

Why P1 and P4 missed: I predicted a rare 1-ulp `cbrt` difference. In fact
**glibc's `cbrt` is not correctly rounded**: against a 60-digit Newton
iteration glibc is correctly rounded in 2159 of 4096 cases, PETIR's `cbrt`
(`libm`) in **4096 of 4096** (scratch check, not committed). The differences
are glibc's, up to 2 ulp in `cbrt`, so up to 3 ulp in `K`. PETIR's rule accepts
1 ulp from the platform libm; this is wider for `K` and is **flagged for the
maintainer**. PETIR was not changed to chase glibc.

### Structural finding: `sphericalHeatTransfer`

| | conductivity read |
|---|---|
| ESI v2506 (`twoPhaseEuler`, `reactingEuler`) | `pair_.continuous().kappa()` |
| Foundation OpenFOAM-dev 852527377c7e | `interface_.dispersed().thermo().kappa()` |
| this port | dispersed (`kappa_d`) |

The port follows Foundation. For ESI the K differs in every cell by
`kappa_d / kappa_c`. Not changed: switching, or offering both, is a decision
for the maintainer. Other ESI/Foundation differences recorded in the
`heat_transfer` module doc: ESI v2506 has no `Gunn`; the default
`residualAlpha` differs.
