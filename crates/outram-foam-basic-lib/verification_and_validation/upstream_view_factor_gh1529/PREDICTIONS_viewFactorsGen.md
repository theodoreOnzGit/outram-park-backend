# Predictions for the viewFactorsGen port (gh:#1540), committed BEFORE any Rust-vs-upstream comparison, 2026-11-14

Upstream: ESI OpenFOAM-v2506 `viewFactorsGen` built `-DNO_CGAL` (octree `distributedTriSurfaceMesh`,
`shootRays.H`), serial, no `finalAgglom` (no agglomeration). Reference files already generated by
gh:#1529 for cubeA, cubeC, cubeD (4x4x4 unit cube), plate4/8/16 (8x8x1 plates in a closed box); one
new case `boxE` (2 x 1 x 0.5 m, 5x3x2 cells, non-square faces) is generated after this file is committed.
Settings are the code defaults (`GaussQuadTol 0.01`, `distTol 8`, `alpha 0.21`; the header comment
of upstream says 0.1, the CODE says 0.01), `writePrecision 17`.

What the Rust port computes: face centres/area vectors (existing `face_centre_and_area`, bit-identical
to ESI per gh:#1489), the ray-start/ray-end candidate test, brute-force segment-vs-triangle visibility,
2AI (far) or 2LI (near) with 1..5-point Gauss-Legendre, the `F`, `globalFaceFaces`, `mapDist` files.

1. **Visible-face lists.** `globalFaceFaces` (the discrete visibility decision) is identical to
   upstream on 100 % of rows of every case. Closed convex enclosure, so the only decisions are the
   two sign tests `(d & fA) < 0` and `(d & remA) > 0`, computed from identical Cf/Sf bits; no ray can
   hit anything. Confidence 97 %.
2. **2AI path (plates, far pairs).** Uses only `+ - * / sqrt`: all correctly rounded, so every 2AI
   entry is bit-identical. Confidence 95 %.
3. **2LI path (cubes).** Uses `log`. Rust uses `petir::mathf::RealMath::r_ln` (ARM optimized-routines
   port, no FMA); this box has glibc 2.39 on a CPU with FMA, whose `log` is the same algorithm
   built with FMA (ifunc `__log_fma`). The two differ by at most 1 ulp in rare cases. Prediction:
   **at least 99.5 % of F entries bit-identical, worst relative difference of an entry below 1e-14**,
   and the residual (if any) attributable to `log`. I put 60 % on exactly 100 % bit-identical.
   If a residual appears I will prove the cause by comparing `r_ln` with the platform `ln` on the
   exact arguments, not accept it unexplained.
4. **Quadrature order.** The order chosen (`gi` at the exit of the tolerance loop) cannot be
   observed in the files, but a different order would change F by more than 1e-3 relative, so
   agreement on prediction 3 implies the same orders.
5. **Files.** `F`, `globalFaceFaces` and `mapDist` written by Rust equal upstream's BYTE FOR BYTE
   (header, `%.17g` formatting included) wherever predictions 1-3 hold; a file with a residual F
   differs only in the digits of the affected entries.
6. **Reciprocity (independent of ESI).** `A_i F_ij` and `A_j F_ji` agree to within the Gauss
   tolerance on the cube: relative difference below 2 % (not gated; reported).
7. **boxE** (not yet generated) behaves like the others: lists identical, F per prediction 2/3.
