# Dynamic mesh (solid-body motion and `meshPhi`) against OpenFOAM.com v2506 (gh:#1380)

Research, education and V&V only (`RESPONSIBLE_USE.md`).

## Methodology

**Subject.** `outram_foam_mesh::dynamic_mesh`: the solid-body motion functions
`linearMotion`, `rotatingMotion`, `axisRotationMotion`, `oscillatingLinearMotion`
(constant coefficients), `septernion`/`quaternion` and `transformPoints`, and the
mesh motion flux `meshPhi` (`face::sweptVol`, `fvGeometryScheme::setMeshPhi`),
driven as `dynamicMotionSolverFvMesh` + `solidBodyMotionSolver` does.

**Reference.** OpenFOAM.com v2506 built by
`scripts/upstream/build-esi-v2506-and-genfoam.sh` (stage `dynmesh` adds
`moveDynamicMesh`; the libraries `libdynamicFvMesh` and `libfvMotionSolvers` come
from the existing stages). The probe `dumpMeshMotion/` repeats `moveDynamicMesh`'s
time loop (`runTime.loop()`, `mesh.update()`) and writes, after each update,
`points`, `meshPhi` (all faces, internal then patches), `faceCentres`, `faceAreas`,
`cellCentres`, `cellVolumes` at `%.17g`. `run_esi.sh` builds it and runs all cases.
The probe only calls ESI classes; no upstream code is copied.

**Inputs.** Meshes `warped3d` (120 hex cells, quads) and `dual_warped3d`
(polyhedral, faces with more than four vertices) from
`../../tests/fixtures/esi_checkmesh/` (ESI `blockMesh` / `polyDualMesh` output, 17
digits). Four `dynamicMeshDict`s in `cases/`; the coefficients (velocity
`(0.3 -0.2 0.1)`, origin `(0.1 0.2 0.3)`, axis `(0.3 0.5 1)`, omega 2.5, degree
rates `(30 -45 60)`, amplitude `(0.2 0.1 -0.3)`, omega 7.3) were fixed before any
run and are arbitrary (not tuned). `deltaT 0.01` (not binary-exact, so the time
accumulation `Time::operator++` is exercised), five steps.

**Pass criterion.** Every value bit-identical (IEEE-754 bit pattern). Round-off
below 1e-8 relative would be acceptable only with an explained cause; none was
needed. Predictions D1 to D7 were committed in `PREDICTIONS.md` before any run.

## Results (2026-11-14, ESI v2506 patch 0, glibc of this machine, `-O3` no FMA)

| Quantity | Values compared | Bit-identical | Worst difference |
|---|---|---|---|
| `points` | 41,400 | 41,400 | 0 |
| `meshPhi` | 25,340 | 25,340 | 0 |
| `faceCentres` | 76,020 | 76,020 | 0 |
| `faceAreas` | 76,020 | 76,020 | 0 |
| `cellCentres` | 19,800 | 19,800 | 0 |
| `cellVolumes` | 6,600 | 6,600 | 0 |
| **All six fields, 2 meshes x 4 motions x 5 steps** | **245,180** | **245,180 (100 %)** | **0** |

Gated by `tests/dynamic_mesh_esi_v2506.rs`:
`solid_body_motion_and_mesh_phi_are_bit_identical_to_the_probe` (240 FNV-1a
hashes in `tests/fixtures/esi_dynmesh_hashes.txt`, always runs) and
`raw_probe_text_is_reproduced_value_by_value_when_available` (set
`DYNMESH_PROBE_DIR=/home/user/upstream-build/gh1380`; it reported 245,180 values
bit-identical). The hash table is regenerated by the ignored test
`regenerate_hash_table`.

**Predictions D1 to D5: all held** (100 % bit-identical, including the glibc
`sin`/`cos` risk named in D2 and the more-than-four-vertex face centres named in
the D4 fallback). **D6 held** (geometric conservation law: per cell
`sum(meshPhi)*deltaT - (V_new - V_old)` below `1e-12*V` for every cell, step and
case; the test `geometric_conservation_law_holds_for_every_cell`). D7 held (linear
points equal `x - (-(v t))`).

**Interpretation.** The ported solid-body motion, the rotation-tensor and
centre-decomposition swept-volume arithmetic reproduce upstream operation for
operation, so the mesh a flow solver would see after `mesh.update()` (points,
geometry, `meshPhi`) is the same bit pattern for these motions. This says nothing
about motion solvers that solve a PDE (`displacementLaplacian`), which are not
ported, nor about topology change.

**What this does not test.** One platform and compiler (`-O3`, no FMA; a build
with `-march=native` would contract and is outside this record); constant
`Function1` coefficients only; serial meshes; all cells moving (`cellZone` limited
motion not ported); time-dependent `Function1` omega (table, sine) not ported.

## Not ported (child issues)

`displacementLaplacian` / `displacementSBRStress` / `velocityLaplacian` and the
other solver-based motion solvers; mesh-motion `pointPatchField` boundary
conditions (`fixedValue` displacement, `angularOscillatingDisplacement`, ...);
non-constant `Function1`; `multiSolidBodyMotionSolver`; `dynamicRefineFvMesh` and the
other topology changers; `sixDoFRigidBodyMotion`; moving-mesh flux correction
(`correctPhi`) and the ALE solver terms.
