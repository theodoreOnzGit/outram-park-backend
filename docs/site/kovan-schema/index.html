Kovan Markdown schema

One Markdown format for literature notes, lessons, deep dives, review walkthroughs and recipes. Any editor, GitHub and any coding agent can read a file in it. Kovan, the workspace's research-notes tool, also reads it as structured data. Decided in issue #743 (2026-10-06).

Research, education and V&V only. Not for reactor operation, licensing, safety decisions or emergency response. This page is an AI-assisted draft and has not been human-reviewed. The schema is being dogfooded: the maintainer is trying it on real documents and may change it.

Headings: what each level means

An artifact is a # heading immediately followed by a fenced toml block that contains a [kovan] table. It runs until the next #. A toml block with no [kovan] table is an ordinary code example and is ignored.

HeadingMeaning
# + [kovan] blockAn artifact. The page's own # title is always the header artifact: # <citekey> with kind = "paper" for a literature note, or the lesson or walkthrough title. No artifact starts at level 2.
##Free prose structure inside the artifact.
###Data. Either CSV series (### start of data series, ### Series: <name> with a fenced csv block, ### end of series) or an embedded code block, such as a walk step's source snippet or a code walk's hops.
the last ##The review sign-off, e.g. ## Review: ✅ rung 3 · Theodore Ong · 2026-10-06 · valid or ## Review: ⚠ AI draft, not reviewed. It is to be generated from review/stamps.toml the signed review.md stamps (corrected 2026-10-10, #825: stamps.toml was removed) and excluded from the content hash (#739). It closes the artifact, so only the next # can follow it.

To the parser, ## and ### are body text. Only a # outside a fence starts a new block, so a # line inside a code block never splits an artifact.

The [kovan] table

KeyRequiredMeaning
idyesStable identifier, unique in the document. Rewording the heading keeps the id, so links survive.
kindyesOne of the kinds below. An unknown kind is reported as a problem with that block, and the rest of the document still loads.
created, modifiedyesRFC 3339 timestamps, e.g. 2026-10-06T09:05:00+08:00.
reviewednoRFC 3339 timestamp of human review. Absent means unreviewed.
origin newno"ai" or "human": who wrote it. Absent means human, so older notes keep their meaning, and it is written back only if it was set. It records authorship, not review: an AI-written artifact stays ai after review, and the review shows in the sign-off. Desktop kovan shows an AI badge.

Beside [kovan], the same TOML block may hold [source] (where in a PDF: page, page + region in page fractions, or pages = [start, end]), [classification] (topics and projects), [extraction] (how a table or graph was digitised), connections (back-pointers to relation artifacts) and relation (see below).

Kinds

kindWhat it is
paperA literature note's header artifact: # <citekey>, the BibTeX record in a latex fence, then a summary.
noteA free-standing note.
annotationA remark anchored to a place in the source PDF ([source]).
source_referenceA pointer to a passage, with no text copied from it.
formulaAn equation in GitHub math.
digitised_tableA table lifted from the source, carried as CSV.
digitised_graphCurves read off a figure, carried as ### CSV series.
relationA typed connector in mindmap.md, with one [relation] table.
mindmapThe mindmap document's header artifact.
lesson_section newA section of a lesson or deep dive: teaching prose, anchored to the code and literature it explains.
walk_step newOne step of a review walkthrough: a claim about one piece of code, its code: anchor, the literature that backs it and the snippet as ### data.
code_walk newA chain of calls through the code, each hop a code: target, with the generated hops carried as ### data.
recipe_step newOne step of a recipe, such as an input deck or a workflow followed by hand.

Relations and anchors

An artifact's links to code and literature are relations, with the existing relation kinds: related_to, supports, contradicts, derived_from, uses_data_from, validates, verified_against and implements. The relation key takes one of two shapes:

  • [relation], a single table. This is the body of a kind = "relation" artifact in mindmap.md, with both source and target written out (unchanged).
  • [[relation]], one or more tables new. These are the anchors of any other artifact. source is omitted because it is the artifact itself.
FieldMeaning
targetWhat it points at (forms below).
kindOne of the relation kinds above.
sourceWritten only in a [relation] artifact.
page newOptional: the 1-based page of a literature target.
quote newOptional: a short quotation from the target, as you would search for it.
commit newOptional: the git commit a code: target was read at.

Target forms

FormExample
A paperpaper:<citekey>
An artifact in a paperartifact:<citekey>#<id>
A topic or projectcollection:htgrs/materials
A typed nodecorpus:concept/nuclear-engineering/thermal-hydraulics, library:literature/<citekey>#<id>
Code newcode:<path/to/file.rs>::<Type::name>[@L<line>], e.g. code:crates/kovan/src/artifact.rs::parse_document. The path is repo-relative, as in a code walk. @L<line> is optional and only tells apart two items with the same name in one file, such as cfg twins.

Desktop kovan shows a code: target as a link card that does not navigate yet; navigation comes with web-kovan. A code: target is never a mindmap node, so it cannot break the map, the wiki or the graph.

TOML, Markdown, JSON

  • TOML and Markdown are for anything a person or an AI writes or reads: literature notes, lessons, walkthroughs, review stamps, Cargo.toml tags and the concept tree.
  • JSON is for machine-generated data that is rebuilt and never edited by hand: code_map.json, the call graph and the link index. It is deterministic (sorted, so the same commit gives the same bytes) and never committed; CI or desktop kovan builds it.

A review walkthrough: header and one walk step (round-trip)

An AI-written walkthrough. The step anchors one function at a pinned commit and cites a page of a paper. Its snippet is ### data, and its last ## is the sign-off, which is hand-written for now. paper:synthetic2020example is a placeholder citekey.

# How kovan finds an artifact's end

```toml

kind = "lesson_section"
created = "2026-10-06T09:00:00+08:00"
modified = "2026-10-06T09:00:00+08:00"
origin = "ai"

[[relation]]
target = "code:crates/kovan/src/artifact.rs::heading_span"
kind = "related_to"
```

The page title is the header artifact. Each step below is its own `#`

A literature note: paper header and an annotation (round-trip)

Kovan writes this shape when you annotate a PDF. It has no origin, so it reads as human-written, and it is written back exactly as it was read. region is a rectangle in page fractions, [x0, y0, x1, y1], measured from the top-left.

# synthetic2020example

```toml
[kovan]
id = "synthetic2020example"
kind = "paper"
created = "2026-08-31T15:04:32+08:00"
modified = "2026-08-31T15:04:32+08:00"

[classification]
topics = ["htgrs/materials"]
```

  author  = {Example, Ada and Placeholder, Ben},
