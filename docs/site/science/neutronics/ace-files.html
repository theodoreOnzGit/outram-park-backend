How is each ACE file put together?

Neutronics

A Monte Carlo code does not read ENDF. It reads ACE files, one per nuclide (the continuous-energy kind) and one per bound scatterer (the thermal kind). Both are written by NJOY's last module, ACER (MacFarlane et al., 2017), from what the earlier modules left behind. Here is what goes into each, using our port's own output at 293.6 K.

The free-gas file: one nuclide, every energy

ENDF evaluation → RECONR → BROADR → HEATR → PURR → ACER

  • RECONR rebuilds the pointwise cross sections from the resonance parameters (pages 12–16) at 0 K, on a grid that makes straight lines between points accurate.
  • BROADR broadens them to the file's temperature (page 22). This is the free-gas treatment of the rate; it covers every energy above the thermal range for every nuclide, and below it for nuclides that are not bound.
  • HEATR adds the heating (KERMA) column. In our port it runs before PURR, as in the NJOY deck, because PURR reads it.
  • PURR makes the unresolved-resonance probability tables (pages 18–19) for nuclides that have an unresolved range. (UNRESR, NJOY's older unresolved module, is not part of this route.)
  • ACER packs all of it, with the angular and energy distributions of each reaction, into one array. The deck's newfor switch selects the "new" cumulative angle distributions (acer.f90:158); our port writes that form.

GASPR (gas production) is also ported, but the one-call route process::ace does not use it. Our route is cross_sections (RECONR, BROADR, HEATR, PURR) followed by ACER (process/mod.rs, acer/mod.rs:493). It keeps one thing besides the ACE file: the 0 K elastic cross section that DBRC needs (page 42), because the ACE file itself carries only the broadened one.

The bound-atom file: one scatterer, thermal energies only

LEAPR deck → S(α,β) → THERMR (with the incident nuclide's own cross sections) → ACER

  • LEAPR turns the phonon spectrum into S(α,β) (pages 23–41). The whole law, whether from a deck or from a published thermal evaluation, is MF=7 data.
  • RECONR and BROADR on the incident nuclide (H-1 for hydrogen in water, C-12 for graphite) supply the grid THERMR works on and the free-atom elastic cross section it needs.
  • THERMR computes, from S(α,β): the incoherent inelastic cross section at each incident energy with its outgoing-energy and angle distributions; the coherent elastic (Bragg) cross section for a crystal, or the incoherent elastic one for a hydrogenous solid, when the evaluation has them. It stops at emax, "maximum energy for thermal treatment" (thermr.f90:135); our default takes it from the law's own upper energy, B(4).
  • ACER, thermal option (acer.f90:465-466, aceth.f90), packs it as a t table: the inelastic energies and cross sections, a fixed number of equally probable outgoing energies for each (each with a fixed number of cosines), and the elastic block.

Our port runs the chain in one call, process::thermal_ace (process/thermal.rs, acer/thermal.rs). It makes the inelastic form NJOY calls iwt = 1 by default (equally probable outgoing energies, IFENG = 0); the skewed (0) and continuous (2) forms are also written (aceth.f90:674-676).

Predict first: look at what the thermal file does not contain. If the code holds H-1's continuous-energy file and the water file, which one supplies hydrogen's capture cross section? Which supplies its scattering at 1 eV? At 20 eV?

What the thermal file leaves out

  • No capture, no fission, no other reaction. Absorption by bound hydrogen is the same as by free hydrogen, to the accuracy that matters, and it stays in the continuous-energy file at every energy.
  • No energies above its limit. The inelastic grid ends at emax: 10 eV for water, 4.9 eV for graphite here. Above it, nothing in the thermal file says how the neutron scatters.
  • No free-gas physics. The thermal file knows nothing of target-velocity sampling or DBRC; its outgoing energies and cosines come straight from S(α,β).
