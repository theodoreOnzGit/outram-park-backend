TRISO-ATOPS: the big picture

Fission products

Chapter 3 followed fission products out of a bare kernel. Chapter 4 added the coatings, and the ways they fail. A reactor holds hundreds of thousands of pebbles, each with thousands of particles. We cannot walk every atom through every particle. A source-term code has to lump: keep what matters for the release, drop the rest. This chapter takes apart one such code, TRISO-ATOPS, piece by piece, and asks of each piece: which lesson did we learn this in, and what does the code keep of it?

What TRISO-ATOPS is

TRISO-ATOPS (“TRISO Analysis Tool for Predictive Source terms”) is a Python tool from Idaho National Laboratory. Its paper says it calculates the release of the key fission products by diffusion through the kernel, the SiC and the graphite, from the fuel and graphite temperatures in normal operation, then their plate-out in the coolant, and then the release in an accident (Stoyer, Raichart & Petti 2026, p. 1). Its equations come from a 1989 model by Petti for the New Production MHTGR, extended from one core node to many (p. 2).

boon-lay carries a Rust port of it. The port is a faithful translation, simplifications included: every number it gives matches upstream’s code (code-to-code verification). That makes it the right place to see what the lumping costs.

The chain, in one breath

For each fuel node and each nuclide: get the diffusion coefficient at the node’s temperature (lesson 41); turn it into a release-to-birth ratio for a failed particle with one model per group (lesson 42); multiply by the fraction of particles that have failed, an input (lesson 43); let the graphite delay the metals; and share what reaches the coolant between circulating, plated out and cleaned up (lesson 44). Then, in an accident, integrate the diffusion over the heat-up and let the coolant gas carry it out while the core heats (lesson 45).

To the predict prompt: none. Intact particles are counted as holding everything (except silver), and a failed particle is a bare kernel with one equivalent sphere. The layers of chapter 4 appear only through the failed fraction.

Where it is in the code

On the Code Review map, the normal-operation chain for one node starts at normal_operation_node: it calls diffusion_coefficient, rb_fail, release_rate and base_activities, then the coolant pools. The accident pieces are in accident and release_models::transient; there is no single accident function in the port (gh:#447).

The theory book’s view

The theory book places TRISO-ATOPS on its fidelity ladder, from CFD down, and lists which constants the HTR-10 digital twin borrows from the MHTGR: step 15, “TRISO-ATOPS: lumped transport”. The TRISO-ATOPS track has its own interactive rungs: to the coolant and into the source term. This chapter does not repeat them; it ties each piece back to chapters 3 and 4.
