Normal operation, node by node

Fission products

Lesson 42 gave the release from a failed particle. Chapter 4 asked how particles fail (lessons 33–36). TRISO-ATOPS does not ask: it takes the failed fractions as inputs and multiplies.

Release rate of one node

normal_operation_node, one node, 1 Ci of inventory, MHTGR Case A constants. The page rescales the code’s rate by your fractions, which is exact because the rate is linear in them (checked below).

Predict first (we did, before running the code): double every failure fraction and the release doubles exactly, for every group except silver, which does not change.

Four fractions, chosen by group

A fuel product line has particles with an exposed kernel from manufacture (fHM), particles with a defective SiC (fSiC), and particles that fail in service, whole (finc) or SiC only (finc,SiC). Which ones matter depends on the group (Stoyer et al. 2026, p. 5):

  • Noble gases and halogens need the whole particle broken: fHM + finc. An intact pyrocarbon holds them even if the SiC is cracked (chapter 4, lesson 31).
  • Metals need only the SiC broken: all four fractions.
  • Silver gets out of intact particles too, so no fraction at all.

The paper also assumes every failed particle sits at the edge of its fuel compact, so the graphite inside the compact holds nothing back (p. 5). The prediction held: doubling the fractions doubles the rate to twelve figures; silver’s does not move.

Where a failed fraction comes from

Chapter 4 computed failure, but for accidents. At the end of normal irradiation at 776 °C, boon-lay fuel failure gives a burst fraction of only … (lesson 36). The bridge FailureFractions::with_fuel_failure_incremental can put it in place of finc. Try it in the panel: Kr-88’s release falls to … of Case A’s (as predicted), Cs-137’s to …. That is not a better answer. In-service failure in real fuel comes from defects that the pressure-vessel model does not describe; the code’s own docs say to use the bridge for a transient, and fuel-qualification data in normal operation.

Where it is in the code

normal_operation_node calls diffusion_coefficient (lesson 41), rb_fail (lesson 42), then release_rate, which picks the fractions by group, then base_activities for the graphite, then the coolant pools (lesson 44). The core is many such nodes, each at one temperature.

Learn more advanced stuff

One temperature per node

Each node has one fuel and one graphite temperature. Chapter 3 showed the kernel itself is nearly isothermal (lesson 17: about 2 K across it), so this is a fair lumping inside a particle; across a pebble or a core it is what the nodes are for.

Case A’s fractions

fHM = 2×10−5, fSiC = 10−4, finc = 2.3×10−5, finc,SiC = 3.6×10−5: the paper’s MHTGR specification and AGR-based values (Table 2, p. 7). They are not HTR-10’s; the theory book compares them (step 15).
