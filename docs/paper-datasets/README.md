# Paper datasets — extracted, not regenerated

Working datasets for three manuscripts in preparation, assembled **from results
already recorded in this repository**. No case was re-run to build these files.

That constraint is deliberate and it is the point: every number here is
traceable to a committed V&V record that was generated by a named command on a
named date. A figure assembled by re-running a case is a *new* measurement
wearing an old label, and the two diverge silently. Extraction keeps the paper
and the repository the same artifact.

to characterise rather than restate.

## Rules for anything added here

1. **Cite the record, not the run.** Every CSV row carries the V&V file it came
   from. If a number has no such file, it does not belong in a paper.
2. **Do not hand-edit a number to match a draft.** If a table disagrees with the
   manuscript, the repository is the authority and the manuscript is what
   changes — the reverse is how published figures stop being reproducible.
3. **Regeneration commands belong in the per-paper README**, so a reader can
   re-derive a row without guessing which test produced it.
4. **Preliminary means preliminary.** Every crate in this workspace is still
   marked ❌ on both bookkeeping axes (`README.md`, "Bookkeeping status"), so no
   result here has maintainer V&V sign-off. Part I handled this correctly by
   titling itself "*Initial* Verification and Validation"; keep that framing.
   See `RESPONSIBLE_USE.md` and `VERIFICATION_AND_VALIDATION.md`.
